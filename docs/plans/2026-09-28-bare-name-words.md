# Одиночное слово в свободном тексте — не название: план реализации

> **Для исполнителя:** навык `superpowers:subagent-driven-development` (рекомендуется) или
> `superpowers:executing-plans`; шаги отмечаются `- [ ]`.

**Цель.** Слой 3 гейта перестаёт закрывать токеном голое одиночное слово, совпавшее с названием
организации или частью ФИО, и продолжает закрывать название в кавычках, с формой собственности,
из нескольких слов и с цифрами или дефисом (Ruling 115).

**Архитектура.** Правило живёт в одной функции `dictionary.name_variants_of`, которая строит ключи
поиска для маскировщика и стража: у одиночного слова голый ключ заменяется узнаваемыми написаниями.
Словари прежних версий пересобирают ключи при открытии (`ВЕРСИЯ_СХЕМЫ` 3 → 4), а чтение ключей и
поиск устаревших ключей отсекают голое слово, дописанное прежней версией шлюза. Слой раскрытого
(`revealed.py`) не меняется.

**Стек.** Python 3.12, SQLite, `ahocorasick_rs`, `pytest`, `hypothesis`, `uv`.

**Проект:** `docs/superpowers/specs/2026-09-28-bare-name-words-design.md` — исполнитель читает его
вместе с планом.

## Общие ограничения

- Одиночное слово — ключ из одних букв без пробелов, дефисов, цифр и прочих знаков:
  `^[^\W\d_]+$` после нормализации (`СВЁРТКА`, нижний регистр).
- Форма собственности в новых ключах — только своя, из самого значения (`ФОРМЫ`).
- `МИНИМАЛЬНАЯ_ДЛИНА_ВАРИАНТА` = 4 и граница слова (Ruling 106) действуют как прежде; ключ в
  кавычках строится только для ядра не короче минимума — как у безбуквенного ядра (Ruling 50).
- Реквизиты (ИНН, ОГРН, счета и другие) детекторы ищут как прежде; правило касается только
  классов `org`/`person` на уровне `identifiers+names`.
- Слой раскрытого значения (Ruling 25, 27) не меняется.
- Токены, написания (`variants`) и журнал не меняются: пересчитываются только ключи
  `name_variants`.
- Код и тексты — по-русски, термины по `CONTEXT.md`; стиль идентификаторов и докстрингов — как в
  окружающем коде (кириллические имена, ссылки на Ruling).
- Команды: `uv run pytest …`, `uv run ruff check .`, `uv run ruff format --check .`; при
  `PYTHONUTF8=1` на Windows, если вывод содержит кириллицу.
- Непрерывная проверка на GitHub не запускается (ошибка оплаты Actions, до 2026-09-30) — перед PR
  полный `uv run pytest -q` локально.

## Отступления от утверждённого проекта (согласовать с владельцем)

1. **Ключ с одной открывающей кавычкой `"ядро`.** 1С обрезает строку без закрывающей «ёлочки»:
   `ООО «Мост` раньше закрывался голым ключом `мост`, а ключами таблицы проекта (`ооо "мост"`,
   `"мост"`, `ооо мост`, `ооо"мост"`) не закрывается ничем — нарушение критерия 2. Ключ `"мост`
   закрывает обрезанное написание; граница слова справа не даёт ему сработать на `"мостовой`.
   Прототип подтвердил: с ним проходят все случаи `test_c1_…` с обрезанной кавычкой.
2. **Ответ с отбором по токену строже ответа без отбора.** Без отбора голое «Мост» в комментарии
   теперь открыто; при отборе `Description eq '[[org:N]]'` слой раскрытого закрывает раскрытое
   значение в любом написании (критерий 3). Открыть его там нельзя: модель узнала бы соответствие
   токена и значения. Это оговорка к Ruling 106 («слой раскрытого без границы слова расходился бы
   с ответом без отбора») и вписывается в текст Ruling 115.
3. **Защита от прежней версии шлюза на том же словаре.** Демон плагина 0.2.x и демон рабочей копии
   поочерёдно открывают один `gate.sqlite`. Старый код при `user_version` 4 пересчёт пропускает и
   пишет новым токенам голые ключи. Поэтому, кроме подъёма версии, голое слово отсекается при
   чтении ключей, и такие токены пересобираются при открытии.

## Что проверить сверх задач (Review Focus)

1. Обрезанная закрывающая кавычка: `ООО «Мост`, `от «Мост` в конце строки закрываются —
   задача 3, тест `test_обрезанная_кавычка_закрыта`.
2. `«Мост»` закрывается одним токеном без висящей `»`: ключи `"мост"` и `"мост` пересекаются, и
   группа `overlaps` обязана выбрать накрывающий — задача 3, `test_кавычки_одним_токеном`.
3. Голое слово, дописанное прежней версией после перехода на 4, в поиск не идёт, а токен получает
   новые ключи — задача 2, `test_голое_слово_прежней_версии_после_пересчёта`.
4. Отбор по токену одиночного названия закрывает голое слово в том же ответе, без отбора — нет —
   задача 3, `test_отбор_по_токену_закрывает_голое_слово`.
5. Оракул property-тестов сверяет выход с ключами словаря, а не с названием, и утечку при
   обрезанной кавычке не увидел бы — задача 4, свойство от самого названия.

def _словарь_с_голым_ключом(путь, версия: int) -> str:
    """Словарь, где у `ООО "Мост"` лежат ключи прежней версии (голое `мост`) при заданной
    `user_version`."""
    словарь = Dictionary(путь, СЕКРЕТ)
    токен = словарь.token_for("org", 'ООО "Мост"', base="ut", entity=К, field="Description")
    словарь.close()
    соединение = sqlite3.connect(путь)
    with соединение:
        соединение.execute("DELETE FROM name_variants WHERE token = ?", (токен,))
        соединение.executemany(
            "INSERT INTO name_variants (token, variant_norm) VALUES (?, ?)",
            [(токен, 'ооо "мост"'), (токен, "мост")],
        )
        соединение.execute(f"PRAGMA user_version = {версия}")
    соединение.close()
    return токен


НОВЫЕ_КЛЮЧИ = {'ооо "мост"', '"мост"', '"мост', "ооо мост", 'ооо"мост"'}

def ушедшие_из_замены(до: str, после: str) -> tuple[list[str], int]:
    """Участки, где «до» стоял токен названия, а «после» — текст; и число обратных участков."""
    ушли: list[str] = []
    обратных = 0
    for вид, а1, а2, б1, б2 in difflib.SequenceMatcher(None, до, после, autojunk=False).get_opcodes():
        if вид != "replace":
            continue
        было, стало = до[а1:а2], после[б1:б2]
        if ТОКЕН_НАЗВАНИЯ.fullmatch(было) and not ЛЮБОЙ_ТОКЕН.search(стало):
            ушли.append("одиночное слово" if _голое_слово(normalize_text_with_map(стало)[0].strip())
                        else форма(стало))
        elif ТОКЕН_НАЗВАНИЯ.fullmatch(стало) and not ЛЮБОЙ_ТОКЕН.search(было):
            обратных += 1
    return ушли, обратных
