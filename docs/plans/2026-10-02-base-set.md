# План: команда `odata1c base set` и запуск команд владельца моделью

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Цель:** команда `odata1c base set <база>` меняет уровень гейта, запись, подпись, роль и скалярные
разрешения записи базы без ручной правки файла баз, а навыки плагина ведут модель так, что она сама
выполняет команды владельца; команды, снижающие защиту, хук переводит в диалог подтверждения.

**Архитектура:** новый модуль `config/base_edit.py` правит файл баз текстом по разметке разбора
PyYAML (`yaml.compose` даёт номера строк ключей), рисует строки помощниками `config/writer.py`,
проверяет результат загрузчиком (`loader.parse_bases`) и пишет атомарно. CLI получает подкоманду
`base set` и перевод вывода в UTF-8. Хук получает правило 4 (`ask` на снижающих командах). Навык
`odata1c-base` новый, `odata1c-policy` переписан на запуск моделью. ADR-0017 закрепляет принцип.

**Стек:** Python 3.12, PyYAML (`compose`, `safe_load`), pydantic (модели настроек), argparse,
pytest, стандартная библиотека в хуке (без зависимостей проекта).

**Проект:** `docs/superpowers/specs/2026-10-01-base-set-design.md` — план аргументирует от него;
исполнитель читает оба.

## Общие ограничения

- Терминология — `CONTEXT.md`: *база*, *роль*, *гейт*, *уровень* (не «режим защиты»), *разрешения*
  (не «права»), *подтверждение* (только диалог разрешения клиента; реплика «да» в чате
  подтверждением не считается — для неё в текстах слово «согласие владельца в отдельном
  сообщении»), *навык*, *хук*, *конструктор политики*.
- Язык кода проекта: публичные имена API по-английски (`set_base_fields`, `parse_bases`,
  `SetResult`), внутренние функции и переменные по-русски, как в соседних модулях. Докстринги
  объясняют «почему», а не пересказывают код.
- **Хук плагина активен в сессии исполнителя**: команда `Bash`/`PowerShell`, в тексте которой
  буквально встречается имя файла баз (`bases` + точка + `yaml`), файла демона или ключа лаунчера,
  отклоняется — в том числе в сообщениях коммитов и heredoc. В командах оболочки пишите «файл баз»;
  в содержимом файлов (код, тесты, документы) имя файла писать можно и нужно — файлы пишутся
  инструментами `Write`/`Edit`, не через оболочку.
- Сессия изолирована в рабочей копии `.claude/worktrees/cli-base-set` (ветка
  `worktree-cli-base-set`): команды git — простые, без подстановок `$(…)` и конвейеров с `git`;
  `git stash` не использовать (общий стек с другими сессиями).
- Реальные значения в выводе: команда `base set` не печатает `url`, `user`, `password` ни в одной
  ветке, включая ошибки; тексты ошибок проверки файла — без значений из файла (формат загрузчика).
- Проверка перед коммитом каждой задачи: `uv run pytest tests/unit -q` по затронутым файлам (полный
  прогон — 8,5 минуты, его делать в задаче 12), `uv run ruff check .`, `uv run ruff format .`.
- Сообщения коммитов — русский, вид `тип(область): что сделано`, последняя строка
  `Co-Authored-By: Claude Fable 5.1 <noreply@anthropic.com>`.

## Review Focus

Пять классов входа, на которых проект молчит, а пользователь споткнётся; у каждого — тест в задаче,
владеющей кодом:

1. **Файл баз с окончаниями строк CRLF** (на Windows `pathlib.write_text` пишет `\r\n`, и файл
   владельца почти наверняка такой): правка не должна смешивать `\n` и `\r\n` и не должна менять
   окончания нетронутых строк — тест `test_crlf_сохраняется` (задача 4).
2. **Подпись с символами разметки** (`#`, `: `, кавычка): строка должна остаться разбираемой, а
   комментарий справа — не «съесть» значение — тест `test_label_с_решёткой_и_кавычкой` (задача 4).
3. **Активный родитель без образца у ребёнка** (владелец сам дописал `permissions:` с одним флагом):
   новое поле вставляется под родителя, а не в конец записи — тест
   `test_вложенное_поле_вставляется_под_активного_родителя` (задача 4).
4. **Команда в цепочке** (`odata1c base list && odata1c base set ut --gate off`): хук должен найти
   снижающую команду не первой — тест `test_base_set_в_цепочке_после_другой_команды` (задача 8).
5. **Вывод на Windows в канале без `PYTHONUTF8`**: кириллица команды читается моделью как UTF-8 —
   тест `test_вывод_cli_в_канале_utf8` (задача 7).

В `src/odata1c/config/loader.py` заменить функцию `_load_bases` целиком на две:

```python
def _load_bases(
    home: pathlib.Path, warnings: list[str]
) -> tuple[str | None, dict[str, BaseConfig]]:
    path = home / "bases.yaml"
    if not path.exists():
        return None, {}
    предупреждение = check_file_permissions(path)
    if предупреждение:
        warnings.append(предупреждение)
    return parse_bases(_разобрать_yaml(path), path, warnings)


def parse_bases(
    data: dict,
    path: pathlib.Path,
    warnings: list[str],
    *,
    resolve_keyring: bool = True,
) -> tuple[str | None, dict[str, BaseConfig]]:
    """Собрать записи баз из уже разобранного содержимого файла баз: умолчания роли, модель
    `BaseConfig`, база по умолчанию. `path` нужен только для текстов ошибок.

    Отдельно от чтения файла — ради `base set` (`config/base_edit.py`): команда проверяет новый
    текст этой же функцией ДО того, как положит его на место исходного файла, и с
    `resolve_keyring=False` — пароль `keyring` остаётся строкой, хранилище ОС не трогается: проверка
    текста не должна зависеть от того, установлен ли пакет keyring и записан ли секрет."""
    raw_bases = data.get("bases") or {}
    if not isinstance(raw_bases, dict):
        raise ConfigError("в bases.yaml раздел bases должен быть словарём «имя базы: настройки»")

    bases: dict[str, BaseConfig] = {}
    for name, raw in raw_bases.items():
        if raw is None:
            warnings.append(f"база «{name}»: запись в bases.yaml пуста, база пропущена")
            continue
        if not isinstance(raw, dict):
            raise ConfigError(
                f"база «{name}»: запись должна быть набором полей (ключ: значение), "
                f"получено {type(raw).__name__}"
            )
        if "name" in raw:
            raise ConfigError(
                f"база «{name}»: ключ name внутри записи базы недопустим — "
                f"имя базы уже задано ключом «{name}» в bases.yaml"
            )
        role = raw.get("role", "prod")
        try:
            resolved = apply_role(role, raw)
        except ConfigError as exc:
            raise ConfigError(f"база «{name}»: {exc}", code=exc.code, hint=exc.hint) from exc
        try:
            bases[name] = BaseConfig(name=name, **resolved)
        except pydantic.ValidationError as exc:
            текст_ошибки = format_validation_error(exc)
            # Файл называется в сообщении, а путь — в подсказке (находка 3 ревью задачи 6 плана
            # M2b): отказ по не прошедшему проверку файлу доходит до модели тем же кодом
            # `config_invalid`, что и битый YAML, а тот файл и место называет. Без имени файла
            # отказ не отличить от ошибки в `daemon.yaml` или в политике.
            raise ConfigError(
                f"bases.yaml: база «{name}» описана неверно: {текст_ошибки}",
                hint=f"проверьте запись базы в файле {path}",
            ) from exc
        if resolve_keyring and bases[name].password == "keyring":
            bases[name] = bases[name].model_copy(update={"password": _из_keyring(name)})

    default = data.get("default")
    if default is not None and not isinstance(default, str):
        raise ConfigError(
            f"default должен быть строкой с именем базы, получено {type(default).__name__}"
        )
    return default, bases
```

Тело цикла — прежнее тело `_load_bases` без изменений, кроме условия `resolve_keyring and`.

```python
# src/odata1c/config/base_edit.py
"""`odata1c base set`: точечная правка записи базы в файле баз без потери комментариев (проект
`docs/superpowers/specs/2026-10-01-base-set-design.md`, §3.2; ADR-0017).

Файл правится текстом по разметке разбора: `yaml.compose` даёт номер строки каждого ключа, по ним
находится блок базы и строки её активных ключей; закомментированные образцы умолчаний
(`# write: false`, `#   mode: off`) находятся регулярным выражением внутри блока. Строки рисуют те
же помощники, что у `base add` (`config/writer.py::строка_записи`), поэтому файл после правки
выглядит так, как будто его написал `base add`: образцы остаются верными, комментарии владельца —
на месте. Почему не `ruamel.yaml`, как у конструктора политики: новый ключ он добавил бы в конец
записи, а закомментированный образец с прежним значением остался бы выше и врал; при смене роли
комментарии «умолчание роли prod» устаревали бы (проект, подход A).

Каждая правка — одна операция над списком строк между двумя разборами: вставка сдвигает номера
строк, и дешевле разобрать файл заново (`_правка`), чем вести сдвиги вручную. Перед записью новый
текст проверяется той же моделью настроек, что читает демон (`loader.parse_bases`); запись атомарна
(`<путь>.yaml.new` + `os.replace`), при любом отказе исходный файл не тронут."""

from __future__ import annotations

import dataclasses
import pathlib
import re
from collections.abc import Callable

import yaml

from odata1c.config.loader import ConfigError

ПО_РОЛИ = object()
"""Значение изменения «снять явное поле — действует умолчание роли» (`--<ключ> default`)."""

ПОЛЯ = (
    "label",
    "role",
    "write",
    "gate.mode",
    "permissions.post_documents",
    "permissions.mark_deletion",
    "permissions.independent_register_delete",
    "permissions.commit_limit",
)
_РОДИТЕЛИ = ("gate", "permissions")
# Поля, чей закомментированный образец показывает умолчание роли: при смене роли перерисовываются
# (`render_base` рисует их по роли записи).
_ОБРАЗЦЫ_ПО_РОЛИ = (
    "write",
    "permissions.independent_register_delete",
    "permissions.commit_limit",
    "gate.mode",
)
# После какой строки вставлять новое поле, если в записи нет ни активной строки, ни образца.
_ПОСЛЕ_КАКИХ = ("role", "password", "user", "url", "label")

# Строка записи: отступ, необязательная решётка с пробелами (образец), ключ, остаток после
# двоеточия. Строки-заголовки (`# --- запись … ---`) и чистые комментарии (`#   # что именно…`)
# под образец не подходят: после решётки у них не ключ с двоеточием.
_КЛЮЧ_RE = re.compile(r"^(?P<indent>[ \t]*)(?P<comm>#[ \t]*)?(?P<key>[A-Za-z_][\w.-]*):(?P<rest>.*)$")


@dataclasses.dataclass
class _Запись:
    """Разметка записи базы в списке строк файла: номера строк 0-based, как `start_mark.line`."""

    начало: int  # строка ключа базы (`  ut:`)
    конец: int  # первая строка после блока записи
    отступ: int  # колонка ключей записи (у `base add` — 4)
    активные: dict[str, int]  # "write" → строка; вложенные — "gate.mode", "permissions.<флаг>"
    родители: dict[str, int]  # активные `gate` / `permissions` → строка ключа раздела


def _ошибка_yaml(exc: yaml.YAMLError) -> ConfigError:
    """Как `loader._разобрать_yaml`: из исключения берётся только место — текст PyYAML вклеивает
    фрагмент файла вокруг ошибки, а в нём может быть пароль."""
    mark = getattr(exc, "problem_mark", None)
    место = (
        f"строка {mark.line + 1}, колонка {mark.column + 1}"
        if mark is not None
        else "точное место в файле не определено"
    )
    return ConfigError(f"файл баз повреждён и не разбирается как YAML: {место}")


def _найти_запись(текст: str, name: str, число_строк: int) -> _Запись:
    try:
        корень = yaml.compose(текст)
    except yaml.YAMLError as exc:
        raise _ошибка_yaml(exc) from exc
    if not isinstance(корень, yaml.MappingNode):
        raise ConfigError("файл баз: ожидался словарь разделов")
    bases_ключ = bases = None
    for k, v in корень.value:
        if k.value == "bases":
            bases_ключ, bases = k, v
    if not isinstance(bases, yaml.MappingNode):
        raise ConfigError("файл баз: раздел bases не найден или не является словарём")
    записи = list(bases.value)
    совпали = [(i, k, v) for i, (k, v) in enumerate(записи) if k.value == name]
    if not совпали:
        известные = ", ".join(sorted(k.value for k, _ in записи)) or "ни одной"
        raise ConfigError(
            f"база «{name}» не описана", code="base_unknown", hint=f"известные базы: {известные}"
        )
    if len(совпали) > 1:
        raise ConfigError(f"база «{name}» описана дважды — поправьте файл вручную")
    i, k, v = совпали[0]
    нестандартная = ConfigError(
        f"база «{name}»: запись в нестандартной форме, поправьте файл вручную",
        hint="нужна запись блоком «ключ: значение» по строкам, как её пишет base add",
    )
    if not isinstance(v, yaml.MappingNode) or v.flow_style or not v.value:
        raise нестандартная
    if i + 1 < len(записи):
        конец = записи[i + 1][0].start_mark.line
    else:
        после_bases = [
            kk.start_mark.line
            for kk, _ in корень.value
            if kk.start_mark.line > bases_ключ.start_mark.line
        ]
        конец = min(после_bases) if после_bases else число_строк
    ключи = [kk.value for kk, _ in v.value]
    if len(set(ключи)) != len(ключи) or "<<" in ключи:
        raise нестандартная
    активные = {kk.value: kk.start_mark.line for kk, _ in v.value}
    родители: dict[str, int] = {}
    for kk, vv in v.value:
        if kk.value not in _РОДИТЕЛИ:
            continue
        if not isinstance(vv, yaml.MappingNode) or vv.flow_style:
            raise нестандартная
        дети = [c.value for c, _ in vv.value]
        if len(set(дети)) != len(дети):
            raise нестандартная
        родители[kk.value] = kk.start_mark.line
        for c, _ in vv.value:
            активные[f"{kk.value}.{c.value}"] = c.start_mark.line
    return _Запись(k.start_mark.line, конец, v.value[0][0].start_mark.column, активные, родители)


def _правка(текст: str, name: str, операция: Callable[[list[str], _Запись], None]) -> str:
    """Одна операция над строками записи между двумя разборами: `операция` меняет список строк на
    месте, пользуясь свежей разметкой."""
    строки = текст.split("\n")
    запись = _найти_запись(текст, name, len(строки))
    операция(строки, запись)
    return "\n".join(строки)
```

```python
def _разделить(rest: str) -> tuple[str, str | None]:
    """`rest` — всё после двоеточия строки записи: значение и, возможно, комментарий справа.
    Кавычки учитываются: `#` внутри `'…'` или `"…"` — часть значения (подпись `УТ #1`, которую
    `_скаляр` заключил в кавычки), а не начало комментария."""
    s = rest.strip()
    if not s:
        return "", None
    if s[0] in "'\"":
        кавычка, i = s[0], 1
        while i < len(s):
            if s[i] == кавычка:
                if кавычка == "'" and s[i + 1 : i + 2] == "'":
                    i += 2
                    continue
                if кавычка == '"' and s[i - 1] == "\\":
                    i += 1
                    continue
                break
            i += 1
        значение, хвост = s[: i + 1], s[i + 1 :].strip()
    else:
        m = re.search(r"\s#", s)
        значение, хвост = (s[: m.start()].rstrip(), s[m.start() :].strip()) if m else (s, "")
    комментарий = хвост[1:].strip() if хвост.startswith("#") else None
    return значение, комментарий


def _собрать(код: str, комментарий: str | None) -> str:
    return _с_комментарием(код, комментарий) if комментарий else код


def _разобрать_строку(строка: str, номер: int) -> re.Match:
    m = _КЛЮЧ_RE.match(строка)
    if m is None:
        # Без текста строки: в ней может быть значение поля.
        raise ConfigError(f"строка {номер + 1} записи базы не разбирается — поправьте файл вручную")
    return m


def _код(отступ: int, ключ: str, текст_значения: str) -> str:
    return " " * отступ + (f"{ключ}: {текст_значения}" if текст_значения else f"{ключ}:")


def _переписать_значение(строка: str, текст_значения: str, номер: int = 0) -> str:
    """Та же строка с новым значением: отступ, решётка образца (если была), ключ и комментарий
    справа сохраняются. Для активной строки — правка по месту, для образца — перерисовка умолчания
    (смена роли, задача 6)."""
    m = _разобрать_строку(строка, номер)
    _, комментарий = _разделить(m.group("rest"))
    код = m.group("indent") + (m.group("comm") or "") + (
        f"{m.group('key')}: {текст_значения}" if текст_значения else f"{m.group('key')}:"
    )
    return _собрать(код, комментарий)


def _активировать(строка: str, текст_значения: str | None = None, номер: int = 0) -> str:
    """Образец становится действующей строкой: решётка снимается, вложенный ключ встаёт на два
    пробела глубже колонки записи (`    #   mode: x` → `      mode: x`), комментарий справа
    остаётся. `текст_значения=None` — значение образца сохраняется (так активируется родитель
    `# gate:`)."""
    m = _разобрать_строку(строка, номер)
    текущее, комментарий = _разделить(m.group("rest"))
    comm = m.group("comm") or ""
    отступ = len(m.group("indent")) + max(len(comm) - 2, 0)
    return _собрать(_код(отступ, m.group("key"), текущее if текст_значения is None else текст_значения), комментарий)


def _закомментировать(строка: str, номер: int = 0) -> str:
    """Активная строка родителя (`    gate:`) снова становится образцом (`    # gate:`)."""
    m = _разобрать_строку(строка, номер)
    return m.group("indent") + "# " + строка[len(m.group("indent")) :]


def _найти_образец(строки: list[str], з: _Запись, поле: str) -> int | None:
    """Закомментированная строка ключа внутри записи с решёткой в колонке записи. Имена ключей не
    пересекаются между уровнями (`mode` только у `gate`, флаги только у `permissions`), поэтому
    вложенность по отступу после решётки не проверяется."""
    ключ = поле.rsplit(".", 1)[-1]
    for n in range(з.начало + 1, з.конец):
        m = _КЛЮЧ_RE.match(строки[n])
        if m and m.group("comm") and m.group("key") == ключ and len(m.group("indent")) == з.отступ:
            return n
    return None


def _место_вставки(з: _Запись) -> int:
    for ключ in _ПОСЛЕ_КАКИХ:
        if ключ in з.активные:
            return з.активные[ключ] + 1
    return з.начало + 1


def _установить(строки: list[str], з: _Запись, *, поле: str, текст: str) -> None:
    """Одно правило на все поля (проект §3.2, п. 4–5): активная строка переписывается; образец
    раскомментируется; нет ни того ни другого — вставка после `role`. Вложенное поле сначала
    активирует родителя; прочие дети родителя остаются образцами."""
    if поле in з.активные:
        n = з.активные[поле]
        строки[n] = _переписать_значение(строки[n], текст, n)
        return
    родитель = поле.split(".")[0] if "." in поле else None
    n = _найти_образец(строки, з, поле)
    if n is not None:
        строки[n] = _активировать(строки[n], текст, n)
        if родитель and родитель not in з.родители:
            p = _найти_образец(строки, з, родитель)
            if p is not None and p < n:
                строки[p] = _активировать(строки[p], None, p)
            else:
                строки.insert(n, " " * з.отступ + f"{родитель}:")
        return
    новая = строка_записи(з.отступ, поле, текст, активна=True)
    if родитель is None:
        строки.insert(_место_вставки(з), новая)
        return
    if родитель in з.родители:
        строки.insert(з.родители[родитель] + 1, новая)
        return
    p = _найти_образец(строки, з, родитель)
    if p is not None:
        строки[p] = _активировать(строки[p], None, p)
        строки.insert(p + 1, новая)
        return
    место = _место_вставки(з)
    строки[место:место] = [" " * з.отступ + f"{родитель}:", новая]

def _умолчание_роли(роль: str, поле: str) -> object:
    узел: object = УМОЛЧАНИЯ_РОЛЕЙ[роль]
    for часть in поле.split("."):
        узел = узел[часть]
    return узел


def _текст_значения(поле: str, значение: object) -> str:
    """YAML-текст значения для строки записи. Подпись идёт через `_скаляр` (кавычки, если в ней
    `#`, двоеточие или апостроф); `role` и `gate.mode` — слова без кавычек, как пишет `base add`
    (`mode: off` без кавычек — форма документации, модель принимает `false` как `off`)."""
    if isinstance(значение, bool):
        return "true" if значение else "false"
    if isinstance(значение, int):
        return str(значение)
    return _скаляр(str(значение)) if поле == "label" else str(значение)


def _значение(данные: dict, поле: str) -> tuple[object, str]:
    """Значение поля записи и его источник: `явно` / `по роли <роль>`; у `label` источника нет."""
    роль = данные.get("role", "prod")
    if поле == "label":
        return данные.get("label", ""), ""
    if поле == "role":
        return роль, "явно" if "role" in данные else "по умолчанию"
    узел: object = данные
    for часть in поле.split("."):
        if not isinstance(узел, dict) or часть not in узел:
            return _умолчание_роли(роль, поле), f"по роли {роль}"
        узел = узел[часть]
    if поле == "gate.mode" and узел is False:
        узел = "off"
    return узел, "явно"

        "gate": "off" if гейт is False else гейт,

            for флаг in (
                "post_documents",
                "mark_deletion",
                "independent_register_delete",

def set_base_fields(path: pathlib.Path, name: str, changes: dict[str, object]) -> SetResult:
    """Применить изменения к записи базы `name` в файле `path` (проект §3.2).

    Все отказы — до правки: неизвестное поле (ошибка вызывающего кода, `ValueError`), файл не
    найден, запись не найдена или в нестандартной форме. Правки применяются по одной (каждая —
    между двумя разборами, `_правка`); затем новый текст проверяется той же моделью настроек, что
    читает демон (`parse_bases`, без обращения к хранилищу ОС), и только после этого ложится на
    место исходного файла атомарно. «Изменений нет» — когда у каждого запрошенного поля совпали и
    значение, и источник: явное значение, равное умолчанию роли, — тоже изменение (как у
    `base add --gate`), файл при «изменений нет» не трогается."""
    for поле, значение in changes.items():
        if поле not in ПОЛЯ:
            raise ValueError(f"неизвестное поле записи базы: {поле}")
        if значение is ПО_РОЛИ and поле in ("label", "role"):
            raise ValueError(f"у поля {поле} нет умолчания роли")
    if not path.exists():
        raise ConfigError(
            f"файл баз не найден: {path}", hint=f"выполните: odata1c init --home {path.parent}"
        )
    try:
        исходный = path.read_bytes().decode("utf-8")
    except UnicodeDecodeError as exc:
        raise ConfigError(f"файл баз не в кодировке UTF-8: {path}") from exc
    # Окончания строк сохраняются как были: на Windows `pathlib.write_text` пишет `\r\n`, и файл
    # владельца почти наверняка такой; правка не должна смешивать `\n` и `\r\n`.
    nl = "\r\n" if "\r\n" in исходный else "\n"
    текст = исходный.replace("\r\n", "\n")
    _найти_запись(текст, name, текст.count("\n") + 1)
    до = yaml.safe_load(текст)["bases"][name]

    новый = текст
    try:
        for поле, значение in changes.items():
            if поле == "role":
                новый = _применить_роль(новый, name, str(значение))
            elif значение is ПО_РОЛИ:
                новый = _снять(новый, name, поле)
            else:
                новый = _правка(
                    новый,
                    name,
                    functools.partial(_установить, поле=поле, текст=_текст_значения(поле, значение)),
                )
        после = yaml.safe_load(новый)["bases"][name]
    except yaml.YAMLError as exc:
        raise ConfigError(
            f"база «{name}»: правка дала неразбираемый файл — файл оставлен нетронутым, "
            "поправьте запись вручную"
        ) from exc

    изменения = [Изменение(п, *_значение(до, п), *_значение(после, п)) for п in changes]
    результат = SetResult(
        label=str(после.get("label", name)),
        изменено=any(и.есть for и in изменения),
        изменения=изменения,
        действует=_действующие(после),
        явные_поля=[
            п for п in ПОЛЯ if п not in ("label", "role") and _значение(после, п)[1] == "явно"
        ],
    )
    if not результат.изменено:
        return результат
    parse_bases(yaml.safe_load(новый), path, [], resolve_keyring=False)
    временный = path.with_suffix(".yaml.new")
    временный.write_bytes((новый.replace("\n", nl) if nl != "\n" else новый).encode("utf-8"))
    os.replace(временный, path)
    закрыть_права_файла(path)
    return результат
```

```python
def _вывод_в_utf8() -> None:
    """Команды CLI теперь читает и модель через канал инструмента Bash (навыки `odata1c-base`,
    `odata1c-policy`, ADR-0017), а на Windows поток Python в канале кодируется кодовой страницей
    (`cp1251`) — кириллица дошла бы искажённой. В настоящей консоли Windows поток и так UTF-8.
    Тот же приём, что у хука плагина (`pretooluse.py::main`). Команда `mcp` исключена:
    её stdout — канал JSON-RPC клиента, им распоряжается лаунчер."""
    for поток in (sys.stdout, sys.stderr):
        with contextlib.suppress(Exception):
            поток.reconfigure(encoding="utf-8")


def _лимит_коммитов(значение: str):
    if значение == "default":
        return значение
    if значение.isdigit():
        return int(значение)
    raise argparse.ArgumentTypeError("целое число (0 — без лимита) или default")


# Ключ командной строки → поле записи базы (`config/base_edit.py::ПОЛЯ`).
_КЛЮЧИ_BASE_SET = (
    ("gate", "gate.mode"),
    ("write", "write"),
    ("label", "label"),
    ("role", "role"),
    ("post_documents", "permissions.post_documents"),
    ("mark_deletion", "permissions.mark_deletion"),
    ("register_delete", "permissions.independent_register_delete"),
    ("commit_limit", "permissions.commit_limit"),
)
_ПОДСКАЗКА_BASE_SET = (
    "укажите хотя бы одно поле: --gate, --write, --label, --role, --post-documents, "
    "--mark-deletion, --register-delete, --commit-limit"
)


def _изменения_base_set(args: argparse.Namespace) -> dict[str, object]:
    изменения: dict[str, object] = {}
    for атрибут, поле in _КЛЮЧИ_BASE_SET:
        значение = getattr(args, атрибут, None)
        if значение is None:
            continue
        if значение == "default":
            изменения[поле] = ПО_РОЛИ
        elif значение == "on":
            изменения[поле] = True
        elif значение == "off" and поле != "gate.mode":
            изменения[поле] = False
        else:
            изменения[поле] = значение
    return изменения


def _показать_значение(поле: str, значение: object) -> str:
    if поле == "permissions.commit_limit":
        return "без лимита" if значение == 0 else str(значение)
    if isinstance(значение, bool):
        return "да" if значение else "нет"
    return str(значение)


def _с_источником(поле: str, значение: object, источник: str) -> str:
    текст = _показать_значение(поле, значение)
    return f"{текст} ({источник})" if источник else текст

    Печатает только изменённые поля «было → стало» с источником и действующее состояние базы.
    Адрес, пользователь и пароль не печатаются ни в одной ветке: команду теперь запускает модель

    `set_base_fields`; настройки читаются заранее, чтобы файл, который не разбирается, дал тот же
    `config_invalid` с путём и строкой, что и у демона, а не отказ посреди правки."""
    if not изменения:
        print(_ПОДСКАЗКА_BASE_SET)
        return 1
    if "label" in изменения and not str(изменения["label"]).strip():
        raise ConfigError("подпись базы не может быть пустой")
    config = load_config(home)
    _печать_предупреждений(config)
    if name not in config.bases:
        raise ConfigError(
            f"база «{name}» не описана в bases.yaml",
            code="base_unknown",
            hint=f"известные базы: {', '.join(sorted(config.bases)) or 'ни одной'}",
        )
    результат = set_base_fields(home / "bases.yaml", name, изменения)
    print(f"база {name} ({результат.label})")
    if not результат.изменено:
        print("изменений нет")
        return 0
    print(f"{'поле':<42}{'было':<30}стало")
    for и in результат.изменения:
        if not и.есть:
            continue
        print(
            f"{и.поле:<42}{_с_источником(и.поле, и.было, и.было_источник):<30}"
            f"{_с_источником(и.поле, и.стало, и.стало_источник)}"
        )
    if "role" in изменения and результат.явные_поля:
        print(f"задано явно, роль не влияет: {', '.join(результат.явные_поля)}")
    д = результат.действует
    р = д["permissions"]
    print(

    )
    return 0
```

```python
def _снижающие_ключи(хвост: str) -> tuple[str, list[str]]:
    """Имя базы и ключи `base set` из хвоста команды, снижающие защиту. Хвост, который не
    разбирается (незакрытая кавычка), считается снижающим целиком: сомнение — в сторону вопроса."""
    try:
        токены = shlex.split(хвост, posix=True)
    except ValueError:
        return "?", ["(хвост команды не разобран)"]
    база, найдено, i = "?", [], 0
    while i < len(токены):
        токен = токены[i]
        if токен.startswith("--") and "=" in токен:
            ключ, значение = токен.split("=", 1)
            i += 1
        elif токен.lower() in _КЛЮЧИ_СО_ЗНАЧЕНИЕМ:
            ключ = токен
            значение = токены[i + 1] if i + 1 < len(токены) else ""
            i += 2
        else:
            if not токен.startswith("-") and база == "?":
                база = токен
            i += 1
            continue
        ключ = ключ.lower()
        if ключ in _ЗАЩИТНЫЕ_ЗНАЧЕНИЯ and значение.lower() not in _ЗАЩИТНЫЕ_ЗНАЧЕНИЯ[ключ]:
            найдено.append(f"{ключ} {значение}".strip())
    return база, найдено


def _команды_владельца(команда: str) -> dict | None:
    """Правило 4: `ask` на `base set` со снижением защиты (все вхождения в цепочке — один вопрос с
    объединённой причиной) и на `policy open`; остальные команды владельца проходят молча."""
    базы: list[str] = []
    ключи: list[str] = []
    for совпадение in _BASH_BASE_SET_RE.finditer(команда):
        база, снижающие = _снижающие_ключи(совпадение.group("хвост"))
        if снижающие:
            базы.append(база)
            ключи.extend(снижающие)
    if ключи:
        return _ask(
            _ПРИЧИНА_BASE_SET.format(база=", ".join(dict.fromkeys(базы)), ключи=", ".join(ключи))
        )
    if _BASH_POLICY_OPEN_RE.search(команда):
        return _ask(_ПРИЧИНА_POLICY_OPEN)
    return None
```

````markdown
# odata1c-base

Настройки базы живут в записи файла баз домашнего каталога шлюза. Файл закрыт от модели (в нём
пароль 1С), поэтому поля записи меняет команда `odata1c base set`, и выполняешь её ты — не
пользователь в терминале (ADR-0017). Демон перечитывает файл перед следующим вызовом тула:
перезапуск не нужен, результат виден сразу в `odata1c_bases`.

## Правило

Команда, снижающая защиту, запускается только после того, как пользователь в отдельном сообщении
явно согласился с тем, что именно ослабнет. Снижают защиту: `--gate` с любым значением, кроме
`identifiers+names`; `--write on`; `--role test` или `dev`; `--post-documents on`,
`--mark-deletion on`, `--register-delete on`; любой `--commit-limit`; `default` у любого ключа.
На такой команде Claude Code покажет диалог разрешения — это ожидаемое подтверждение; отказ в нём
означает «не делать»: остановись и сообщи. Повышающие и нейтральные команды (`--write off`,
`--gate identifiers+names`, `--role prod`, выключение разрешений, `--label`) выполняй сразу после
того, как назвал, что изменится.

Не делай никогда: не читай и не правь файлы домашнего каталога шлюза; не передавай команде адрес,
пользователя или пароль (у неё и нет таких ключей); не придумывай значения, которых пользователь
не называл; не запускай `odata1c base add` (она спрашивает пароль — это команда для терминала
человека, навык `odata1c-setup`).

## Шаги

1. **Текущее состояние.** Вызови `odata1c_bases`: имя, подпись, роль, уровень гейта и запись
   каждой базы. Если баз несколько и из просьбы не ясно, о какой речь, спроси.

2. **Переведи просьбу в ключи команды.** Одна команда на базу; ключи:

   ```text
   odata1c base set <база> [--gate off|identifiers|identifiers+names|default]
                           [--write on|off|default]
                           [--label "<подпись>"]
                           [--role prod|test|dev]
                           [--post-documents on|off|default]
                           [--mark-deletion on|off|default]
                           [--register-delete on|off|default]
                           [--commit-limit <число>|default]
   ```

   `default` возвращает поле к умолчанию роли. `--register-delete` — удаление записей независимых
   регистров сведений (`odata1c_delete_record`). `--role` меняет умолчания всех полей, которые не
   заданы явно: у базы без явных полей `--role dev` разом выключает гейт и включает запись — скажи
   об этом до запуска. Умолчания ролей: `prod` — гейт `identifiers+names`, только чтение, лимит 20;
   `test` — `identifiers`, запись, лимит 50; `dev` — гейт выключен, запись, без лимита.

3. **Назови, что изменится, словами** — одним сообщением, без команды, если есть снижение защиты:
   «гейт `trade_dev` будет выключен: названия контрагентов, ИНН, телефоны и адреса пойдут в ответах
   открытыми» или «запись в `ut_prod` будет разрешена: модель сможет готовить изменения, каждое —
   с подтверждением». Дождись согласия в следующем сообщении. Без снижения защиты — просто скажи,
   что делаешь, и переходи к шагу 4.

4. **Выполни команду** через Bash: `odata1c base set …`. Если ответ — «команда не найдена»,
   запусти ту же команду как `uvx --from odata1c-gate odata1c base set …`. Инструмент PowerShell
   для этого не используй: он может исказить кириллицу вывода.

5. **Покажи вывод пользователю как есть** — таблицу «поле, было, стало» и строку «действует:».
   Реквизитов в выводе нет. «Изменений нет» — поле уже такое; скажи об этом. Отказ `base_unknown`
   — проверь имя по `odata1c_bases`; `config_invalid` с путём и строкой — файл баз повреждён,
   отдай путь и строку пользователю: править его может только он.

6. **Проверь результат** повторным `odata1c_bases`: новый уровень гейта и запись видны в строке
   базы. Смена уровня гейта посреди сессии ещё и придёт строкой `warnings` в следующем ответе
   любого тула — это нормально.

## Чего команда не умеет

Адрес публикации, пользователь и пароль 1С, новая база — только `odata1c base add` в терминале
человека (навык `odata1c-setup`). Списки сущностей и полей для записи (`allow_entities`,
`deny_entities`, `deny_fields`) и флаг `register_direct_write` — ручная правка файла баз
владельцем по закомментированным строкам его шаблона. Удаление базы — тоже ручная правка; команды
для этого нет намеренно. Что скрывать внутри базы (поля, сущности) — навык `odata1c-policy`.
````

````markdown
# Команды владельца выполняет модель через CLI; снижение защиты проходит через подтверждение человека

ADR-0015 отдал правку политики конструктору `odata1c policy …` и закрепил, что команду набирает и запускает владелец в своём терминале, а модель лишь печатает её: содержимое полей 1С может подтолкнуть модель открыть поле, которое открывать не просили. Полей записи базы — уровня гейта, записи, подписи, роли, разрешений — это не касалось вовсе: команды для них не было, владелец правил `bases.yaml` руками, а файл закрыт от модели хуком (в нём пароль 1С). Владелец решил 2026-10-01 (проект `docs/superpowers/specs/2026-10-01-base-set-design.md`): он управляет базами шлюза в диалоге с моделью — «сделай `trade_dev` только для чтения с полным гейтом», — и модель делает это сама; в терминал он не ходит, файл с паролем модель по-прежнему не видит. Выбрано: появляется команда `odata1c base set` для полей записи базы и скалярных разрешений; модель выполняет её и команды конструктора политики сама по навыкам плагина; команда, которая **снижает защиту** (уровень гейта ниже `identifiers+names`, включение записи, роль `test`/`dev`, включение разрешения, любой лимит коммитов, возврат поля к умолчанию роли, `policy open`), выполняется только после явного согласия владельца в отдельном сообщении, и хук плагина переводит её в диалог разрешения Claude Code — тот же человеческий барьер, что страхует `odata1c_commit`. Тула MCP для настроек и политики по-прежнему нет.

## Considered Options

- **Оставить терминал владельца** (ADR-0015 как есть, `base set` — тоже команда для терминала). Отвергнуто владельцем: цель — управлять шлюзом в диалоге, а не диктовать команды; модель и так видит всё, что печатает команда (реквизитов там нет).
- **Тул MCP с подтверждением по `_meta`**, как у `odata1c_commit`: работает в любом клиенте, не зависит от хука и от `PATH`. Отвергнуто: демону не нужен путь записи в собственную конфигурацию; конструктор политики остался бы отдельным механизмом с другим правилом, а решение ADR-0015 «тула MCP для политики нет» сохраняется — данные 1С не должны иметь прямой дороги к настройкам защиты через протокол модели.
- **Собственное интерактивное подтверждение команды** (вопрос в терминале при снижении защиты). Отвергнуто: у Bash модели нет терминала, `--yes` или `yes |` обходят вопрос одной строкой; человеческий барьер должен лежать вне канала, которым распоряжается модель.
- **Модель выполняет всё без разделения** на снижающие и повышающие команды, последняя линия — разрешения Claude Code на Bash. Отвергнуто: в автоматическом режиме Bash текст из данных 1С с инъекцией выключил бы гейт одной командой; разделение стоит одного лишнего диалога.

## Consequences

- `odata1c base set <база>` меняет `gate.mode`, `write`, `label`, `role`, `permissions.post_documents`, `permissions.mark_deletion`, `permissions.independent_register_delete`, `permissions.commit_limit`; значение `default` снимает явное поле. Файл правится текстом по разметке разбора PyYAML, строки не затронутых полей и комментарии владельца сохраняются байт в байт, образцы умолчаний остаются верными и после смены роли; новый текст проверяется моделью настроек демона до записи, запись атомарна. Явное значение пишется явно и при совпадении с умолчанием роли (как `base add --gate`). Адрес, пользователь и пароль командой не меняются и не печатаются. Записи в нестандартной форме (поточные, с ключом слияния) не правятся. Списки сущностей и полей — вне первой поставки.
- Хук `PreToolUse` получает правило 4: `odata1c base set` со снижающими ключами и `odata1c policy open` → `ask` с перечнем ключей в причине; хук не знает текущих значений и роли, поэтому `--gate identifiers`, любой `default` и любой `--commit-limit` считает снижением. Прочие команды владельца проходят молча. `deny` правила 3 (`reveal`, файлы дома) старше.
- Навыки: новый `odata1c-base`; `odata1c-policy` разрешает модели запускать `hide` (с `--yes`: у Bash нет терминала, вопрос о дочерних сущностях переезжает в сообщение модели) и `set`, `open` — после согласия и с диалогом; `odata1c-setup` отсылает к `odata1c-base`; `odata1c` снимает запрет «не выполнять `odata1c policy …`». `base add` (пароль), `reveal` и `doctor` остаются за человеком. Тема `odata1c_info("policy")` говорит то же.
- Вывод всех команд CLI в канале — UTF-8 (`cli.main`): его читает модель через Bash, а на Windows поток в канале кодировался бы кодовой страницей.
- Пределы (SPEC §11.2, CONTEXT.md «Хук»): хук — защита в глубину, не барьер. Поведение `ask` в режимах `bypassPermissions` и `dontAsk` документацией Claude Code не описано; клиент без хуков диалога не покажет. Последняя линия — согласие владельца в отдельном сообщении по навыку и разрешения Claude Code на Bash; полноценная защита — аутентификация человека (M4). Согласие в сообщении подтверждением по CONTEXT.md не является — подтверждение здесь только диалог разрешения. `uvx` без закрепления ставит последнюю версию пакета, а плагин закрепляет версию демона: `base set` пишет только давно существующие поля, расхождение версий файл не портит; навык предпочитает `odata1c` с `PATH`.
- CONTEXT.md: статья «Конструктор политики» — команды выполняет модель; новый термин «Снижение защиты»; «Хук» — правило 4; «Навык» — навыков пять. SPEC §3.1, §3.5, §6.9, §11.2, §11.3.
````
