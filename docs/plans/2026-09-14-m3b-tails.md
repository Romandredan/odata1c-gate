# M3b (хвосты и остатки) Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** закрыть накопленные хвосты этапов M1d–M3 — утечку названия рядом со своим токеном,
мелочи гейта, замок реиндекса, `LineNumber`, табличные части и `Edm.Int64` при записи,
предел подготовок, `expand` в рецептах,

политики `custom`/`copy` — и выпустить `0.2.0`.

**Architecture:** тот же пакет `odata1c` (демон, лаунчер, CLI) и тот же плагин `plugin/`. Гейт
получает второй проход маскировщика и четыре точечные правки классификаторов; слой записи —
правила строк табличных частей и сериализацию `Edm.Int64`; слой настроек — пароль из хранилища ОС, отложенный до создания клиента базы;
плагин — четвёртый навык. Ни одного нового процесса и ни одного нового файла настроек.

**Tech Stack:** Python ≥ 3.12, `uv`, `hatchling`, `mcp` ≥ 2.2 (`MCPServer`, Streamable HTTP),
`httpx`, `httpx2`, `pydantic`, `pyyaml`, `ruamel.yaml`, `lxml`, `starlette` (приходит с `mcp`,
здесь объявляется прямо), `keyring` ≥ 25 (становится обычной зависимостью); Claude Code
(`claude plugin validate|eval`); GitHub Actions; PyPI trusted publishing.

**Spec:** `docs/superpowers/specs/2026-09-14-m3b-tails-design.md` (разделы 1–14; номера разделов
проекта указаны в каждой задаче). Первичные документы: `SPEC.md` §3.4, §3.5, §4, §5, §6.4–6.7,

```python
# tests/unit/test_bump_version.py — дописать
def test_plugin_json_канонический_и_bump_меняет_одну_строку() -> None:
    """м-9 итогового ревью M3: манифест хранится ровно в той форме, в какой его пишет
    `bump_version._записать_json`. Иначе первый же выпуск перекладывает весь файл, и разница
    коммита выпуска не читается глазами.

    Тест ничего не переписывает: он сравнивает файл с его же канонической сериализацией и
    отдельно считает, сколько строк изменила бы подмена версии. `strict=True` у `zip` заодно
    ловит изменение ЧИСЛА строк."""
    путь = КОРЕНЬ / "plugin/.claude-plugin/plugin.json"
    текст = путь.read_text(encoding="utf-8")
    данные = json.loads(текст)
    assert текст == json.dumps(данные, ensure_ascii=False, indent=2) + "\n"

    данные["version"] = "9.9.9"
    новый = json.dumps(данные, ensure_ascii=False, indent=2) + "\n"
    различия = [
        (было, стало)
        for было, стало in zip(текст.splitlines(), новый.splitlines(), strict=True)
        if было != стало
    ]
    assert len(различия) == 1
```

```python
ПОРТ_ДЕМОНА = 7191
СУЩНОСТЬ = "Catalog_БанковскиеСчета"
ПОЛЕ_КЛАССА = "Владелец/Description"   # название лежит в поле с классом
ПОЛЕ_ТЕКСТА = "Наименование"           # и оно же — внутри свободного текста строки


async def раздел_два_прохода(вызов) -> list[dict]:
    """Один запрос к сущности, где название лежит и в поле с классом, и в свободном тексте.

    Находка засчитывается по ФОРМЕ, а не по значению (инвариант 1, Global Constraints): из
    ответа берётся только признак «в свободном тексте остался открытый фрагмент, который в
    соседнем поле закрыт токеном» и форма этого фрагмента (`форма()`: цифра → 9, буква → a).
    """
    ответ = await вызов(
        "odata1c_query",
        {
            "base": БАЗА,
            "entity": СУЩНОСТЬ,
            "select": [ПОЛЕ_КЛАССА, ПОЛЕ_ТЕКСТА],
            "expand": ["Владелец"],
            "top": 50,
        },
    )
    находки = []
    for запись in json.loads(ответ)["items"]:
        текст = запись.get(ПОЛЕ_ТЕКСТА) or ""
        токен = (запись.get("Владелец") or {}).get("Description") or ""
        if not parse_token(токен):
            continue
        открытые = [
            кусок
            for кусок in _слова(текст)
            if len(кусок) >= 4 and not parse_token(кусок) and _похоже_на_название(кусок)
        ]
        if открытые:
            находки.append({"поле": ПОЛЕ_ТЕКСТА, "формы": sorted({форма(к) for к in открытые})})
    return находки
```

`форма(строка)` — цифра → `9`, буква → `a`, прочее как есть (взять из
`contact_info_live_check.py`, там она уже есть). `_похоже_на_название` — слово с заглавной буквы
или в кавычках длиной ≥ 4; `_слова` — разбиение по небуквенно-цифровым символам с сохранением
кавычек. Ключ `--label до|после` пишет отчёт с этой пометкой.

```python
# M-7 (хвост M1d): пара `"odata.count": "<цифры>"` верхнего уровня ответа. Три шаблона по
# порядку, а не один с необязательными запятыми с обеих сторон: жадная форма
# `(?:,\s*)?…(?:\s*,)?` на счётчике ПОСРЕДИ объекта съедает обе запятые и оставляет невалидный
# JSON. Первый шаблон забирает запятую справа, второй — слева, третий — счётчик как
# единственный ключ. Кавычки вокруг цифр необязательны: JSON OData v3 отдаёт счётчик строкой
# (проба P4), но числовая форма ранним проходом задевалась бы так же.
_СЧЁТЧИК_ШАБЛОНЫ = (
    re.compile(r'"odata\.count"\s*:\s*"?(\d+)"?\s*,'),
    re.compile(r',\s*"odata\.count"\s*:\s*"?(\d+)"?'),
    re.compile(r'"odata\.count"\s*:\s*"?(\d+)"?'),
)


def _вынуть_счётчик(text: str) -> tuple[str, int | None]:
    """Текст ответа без пары `odata.count` и её значение числом (`None` — пары нет).

    Счётчик — служебное поле шлюза (SPEC §5.1, `response.strip_service`), а не данные 1С: ранний
    проход по сырому телу (Ruling 25) не должен видеть его вовсе. Возвращается он уже в
    РАЗОБРАННЫЙ ответ, а не в текст: тогда смещения замен, которые ранний проход запоминает для
    `load_scrubbed` (Ruling 32), считаются по тому же тексту, который разбирается."""
    for шаблон in _СЧЁТЧИК_ШАБЛОНЫ:
        совпадение = шаблон.search(text)
        if совпадение is not None:
            без_счётчика = text[: совпадение.start()] + text[совпадение.end() :]
            return без_счётчика, int(совпадение.group(1))
    return text, None
```

```python
def _порт_из_daemon_yaml(home: pathlib.Path) -> int:
    """Порт демона для опроса — своим мелким разбором `daemon.yaml`, а не `load_config`: битый
    `bases.yaml` не должен мешать остановить демон. Та же причина и та же форма, что у
    `doctor._порт_демона`; дублирование намеренное — `doctor` импортирует `daemon`, обратный
    импорт замкнул бы цикл."""
    путь = home / "daemon.yaml"
    if путь.exists():
        try:
            данные = yaml.safe_load(путь.read_text(encoding="utf-8")) or {}
        except (OSError, yaml.YAMLError):
            return DaemonConfig().port
        порт = данные.get("port") if isinstance(данные, dict) else None
        if isinstance(порт, int):
            return порт
    return DaemonConfig().port


def спросить_демон(port: int, *, timeout: float = 1.0) -> int | None:
    """Номер процесса демона, отвечающего на `port`, или `None` — ответил не как наш демон
    (404 у версии до M3b, чужой процесс на порту), ответил мусором или не ответил вовсе.

    Порт эта функция НЕ проверяет: живость порта вызывающий (`остановить`) выясняет сам одним
    вызовом `is_listening` — ему нужно РАЗЛИЧАТЬ «порт молчит» и «порт отвечает, но номера не
    назвал», а по одному `None` их не различить. Первое значит, что pid-файл осиротел; второе —
    что перед нами демон прежней версии, и снимать его надо по номеру из файла. Спутать их
    значило бы отказаться останавливать ровно тот демон, который останавливают, чтобы поднять
    новый код."""
    try:
        with urllib.request.urlopen(
            f"{daemon_url(port).rstrip('/')}/alive", timeout=timeout
        ) as ответ:
            данные = json.loads(ответ.read().decode("utf-8"))
    except Exception:  # noqa: BLE001 — см. докстринг: любой сбой опроса здесь равнозначен None
        return None
    pid = данные.get("pid") if isinstance(данные, dict) else None
    return pid if isinstance(pid, int) and pid > 0 else None
```

```python
def остановить(
    home: pathlib.Path, *, port: int | None = None, force: bool = False
) -> ИтогОстановки:
    """… прежний докстринг сохраняется целиком …

    Проект M3b §8. Прежде решение принималось по одному только `daemon.pid`, а номер процесса в
    нём после перезагрузки может принадлежать кому угодно. Теперь первым спрашивается сам демон
    по своему порту (`спросить_демон`), и порядок такой:

    1. порт назвал номер — снимается НАЗВАННЫЙ процесс, а не тот, что записан в файле: файл мог
       отстать (демон перезапускался и не успел его переписать) или не существовать вовсе;
    2. порт отвечает, но номера не назвал (демон версии до M3b) — прежнее поведение: номер из
       файла;
    3. порт молчит — файл осиротел: он удаляется, НИ ОДИН процесс не трогается, и это говорится
       вслух;
    4. `force=True` — порт не спрашивается вовсе: прежнее поведение для демона, который порт
       слушает, а отвечать перестал.

    `port` — явный порт для тестов и для вызывающего, который его уже знает; `None` — из
    `daemon.yaml` этого домашнего каталога.
    """
    pid_файл = home / "daemon.pid"
    содержимое = _прочитать_pid_файл(pid_файл)
    порт = port if port is not None else _порт_из_daemon_yaml(home)
    # Один вызов `is_listening` на всю функцию: он же отличает исход 2 от исхода 3.
    отвечает = False if force else is_listening(порт, timeout=0.5)
    названный = спросить_демон(порт) if отвечает else None

    if названный is not None:
        цель = названный                                    # исход 1
    else:
        if содержимое is None:
            if not pid_файл.exists():
                return ИтогОстановки("нет_файла", f"демон не запущен: {pid_файл} не найден")
            return ИтогОстановки(
                "не_разобран",
                f"не удалось остановить демон: {pid_файл} не читается — номер процесса из него "
                "не узнать; удалите файл, если ни один демон не работает",
            )
        if not содержимое:
            # Пустой файл — не обязательно мусор: `_записать_pid_файл` атомарен, но файл,
            # записанный иначе (руками, прежней версией), читатель может застать пустым.
            return ИтогОстановки(
                "не_разобран",
                f"не удалось остановить демон: {pid_файл} пуст — номера процесса в нём нет; "
                "если демон только что запускается, повторите команду через секунду, если ни "
                "один демон не работает — удалите файл",
            )
        if not force and not отвечает:
            # Исход 3: порт молчит. Файл — единственный источник, и он ничем не подтверждён;
            # номер из него может принадлежать чужому процессу, которому ОС отдала номер после
            # перезагрузки. Снимать по нему нельзя — можно только убрать сам файл.
            _убрать_pid_файл(pid_файл, содержимое)
            return ИтогОстановки(
                "осиротел",
                f"демон по {pid_файл} не отвечает на порту {порт}: pid-файл считается "
                "осиротевшим и удалён, никто не остановлен",
            )
        try:
            цель = int(содержимое)                          # исходы 2 и 4
        except ValueError:
            return ИтогОстановки(
                "не_разобран",
                f"не удалось остановить демон: {pid_файл} не содержит номера процесса — демон "
                "по нему не остановить; удалите файл, если ни один демон не работает",
            )

    отказ: OSError | None = None
    try:
        os.kill(цель, signal.SIGTERM)
    except OSError as ошибка:
        отказ = ошибка

    if not _дождаться_смерти(цель, ОЖИДАНИЕ_СМЕРТИ_ДЕМОНА_С):
        return ИтогОстановки(
            "жив",
            f"не удалось остановить демон: процесс {цель} жив через "
            f"{ОЖИДАНИЕ_СМЕРТИ_ДЕМОНА_С:.1f} с после попытки снять, pid-файл оставлен на месте"
            + (f"; os.kill отказал: {отказ}" if отказ is not None else ""),
        )

    if содержимое is not None:
        # Файл убирается по СВОЕМУ прежнему содержимому (находка Б.7): между чтением и удалением
        # умещается целый перезапуск демона, и безусловный `unlink` унёс бы pid-файл живого
        # нового. Файла могло не быть вовсе (демон назвал номер сам) — тогда убирать нечего.
        _убрать_pid_файл(pid_файл, содержимое)
    return ИтогОстановки("снят", f"демон остановлен (процесс {цель})")
```

```python
ПОЛЕ_НОМЕРА_СТРОКИ = "LineNumber"


def _проставить_номера_строк(часть: str, строки: list[dict]) -> list[dict]:
    """Номера строк табличной части по правилу проекта M3b §5.1.

    Ни одна строка номера не несёт — шлюз нумерует 1..n в порядке тела: без `LineNumber` 1С
    отвечает HTTP 500 «внутренняя ошибка OData сервиса» уже ПОСЛЕ подтверждения пользователя
    (известное ограничение записи M2, `docs/probes/M2-live-check.md`).

    Несут все — номера проверяются: положительные целые без повторов. Порядок строк в теле при
    этом не меняется: номер — данные строки, а не её место в массиве.

    Несут не все — отказ: вставить ненумерованные между нумерованными можно несколькими
    способами, и любой из них шлюз выбрал бы за пользователя молча.
    """
    с_номером = [строка for строка in строки if ПОЛЕ_НОМЕРА_СТРОКИ in строка]
    if not с_номером:
        return [
            {ПОЛЕ_НОМЕРА_СТРОКИ: номер, **строка}
            for номер, строка in enumerate(строки, start=1)
        ]
    if len(с_номером) != len(строки):
        raise WriteError(
            "params_invalid",
            f"табличная часть «{часть}»: LineNumber либо у всех строк, либо ни у одной",
            hint="уберите LineNumber везде — шлюз пронумерует строки по порядку тела",
        )
    номера = [строка[ПОЛЕ_НОМЕРА_СТРОКИ] for строка in строки]
    if any(not isinstance(н, int) or isinstance(н, bool) or н < 1 for н in номера):
        raise WriteError(
            "params_invalid",
            f"табличная часть «{часть}»: LineNumber — целое число больше нуля",
        )
    if len(set(номера)) != len(номера):
        raise WriteError(
            "params_invalid", f"табличная часть «{часть}»: LineNumber повторяется"
        )
    return строки
```

```python
    def _с_паролем(self, base: BaseConfig) -> BaseConfig:
        """Запись базы с настоящим паролем: `password: keyring` разрешается ЗДЕСЬ, а не в
        загрузчике (SPEC §3.4, проект M3b §6.1).

        Отказ закрывает тулы ТОЛЬКО этой базы — `password_missing` с подсказкой
        `odata1c base secret <имя>`; клиент при этом не создаётся и не кэшируется, поэтому
        секрет, записанный владельцем при работающем демоне, действует со следующего же вызова
        тула, без перезапуска."""
        if base.password != secrets.ЛИТЕРАЛ:
            return base
        try:
            пароль = secrets.пароль_базы(base.name)
        except secrets.KeyringUnavailable as ошибка:
            raise _ServiceError(
                "password_missing",
                f"пароль базы «{base.name}» хранится в хранилище ОС, а хранилища в системе нет",

            ) from ошибка
        if пароль is None:
            raise _ServiceError(
                "password_missing",
                f"пароль базы «{base.name}» не найден в хранилище ОС",
                f"запишите его: odata1c base secret {base.name}",
            )
        return base.model_copy(update={"password": пароль})
```

```python
    путь навыка `odata1c-setup`. На других ОС `--window` печатает «выполните в своём терминале:
```

```python
def add_custom_class(
    path: pathlib.Path, name: str, fields: list[str], regex: str | None
) -> None:
    """`policy custom`: свой класс гейта — `custom.<name>` в `policy.yaml` (SPEC §6.9).

    Класс описывается именами полей (поле с таким именем В ЛЮБОЙ сущности) и/или выражением для
    поиска по содержимому (действует, когда у базы включён `scan_free_text`). Нужен хотя бы один
    из двух: класс без признаков не закрывает ничего.

    Само выражение компилируется ВЫЗЫВАЮЩИМ до записи (CLI): негодное выражение, попавшее в
    файл, закрыло бы владельцу все тулы базы кодом `config_invalid` — файл политики читается на
    каждом вызове.

    Назначить этот класс полю — уже существующей командой `policy set … custom:<name>`: одна
    команда объявляет класс, другая применяет, и путать их не нужно."""
    yaml_rt, данные = _открыть(path)
    свои = _раздел(данные, "custom")
    правило = CommentedMap()
    if fields:
        правило["fields"] = list(fields)
    if regex is not None:
        правило["regex"] = regex
    свои[name] = правило
    _сохранить(yaml_rt, данные, path)


def copy_policy(src: pathlib.Path, dst: pathlib.Path) -> None:
    """`policy copy`: файл политики владельца целиком, вместе с комментариями (ADR-0015).

    Копируется именно ФАЙЛ ВЛАДЕЛЬЦА (`policy.yaml`), а не действующая политика: раздел `auto`
    живёт в `policy.auto.yaml` и принадлежит индексу ЦЕЛЕВОЙ базы — переносить его значило бы
    подменить цели её собственную авторазметку разметкой чужого `$metadata`.

    Запись атомарна тем же приёмом, что у `_сохранить`: временный файл рядом и `os.replace`."""
```

## Самопроверка плана

Проведена после написания; найденное исправлено прямо в тексте выше.

1. **Покрытие.** Каждый раздел проекта закрыт задачей — таблица выше. Разделов без задачи нет.
2. **Заглушек нет.** Развилки по отчёту P9 не оставлены на усмотрение исполнителя формулой
   «сузить бриф»: обе ветки P9-6 и P9-8 написаны конкретным кодом и конкретным тестом
   (задача 6 шаги 6 и 9; ветки P9-1/P9-3 ушли вместе с задачей 7, Ruling 100). Нигде не сказано «как в задаче N» — код
   повторяется там, где нужен. Два места, где сначала стояло «сюда переносится существующий
   код», переписаны: разделяемая перестройка сведена к одному вызову `rebuild_index` (задача 4,
   шаг 4), а `остановить` выписана целиком, со всеми пятью исходами (задача 4, шаг 9).
3. **Согласованность имён.** Сверено между задачами: `rows_diff`/`RowsDiff` (задача 6 →
   задача 9, раздел `часть_update`); `PendingStore.count_live` и код `pending_limit` (6 → 9,
   раздел `предел`); `Recipe.expand` (8 → 9, раздел
   `рецепты`); `add_custom_class`/`copy_policy` (12); `password_missing` и
   `secrets.ЛИТЕРАЛ` (10 → 11, навык); `GET /alive` с полем `pid` (4 → 9, раздел `стоп`);
   (`Посредник1С(..., удалять=…)` снят вместе с регистрами, Ruling 100).
4. **Отклонения от буквы проекта — названы, а не сделаны молча.**
   - §3.8 просит `asyncio.Lock` вокруг `reindex` в `daemon.py`. В плане — словарь текущих задач
     в `ToolService.reindex`, и разделяется ровно `rebuild_index` (задача 4, шаг 4). Причина:
     обычный замок заставил бы второй вызов ПОВТОРИТЬ перестройку, а проект требует, чтобы он
     «получил результат первого»; и оба вызывающих (тул демона и фоновая проверка `$metadata`)
     идут через `ToolService.reindex`, а не через `daemon.py` напрямую. Тест проверяет именно
     это: `$metadata` скачан один раз. Пересборка политики и стража осталась у каждого
     вызывающего — она идемпотентна, и переносить её в общий метод значило бы вынимать из
     замыкания шесть десятков строк ради нуля выигрыша.
   - §8 описывает три исхода `stop()`. В плане их четыре (задача 4, шаг 9): добавлен «порт
     отвечает, но номера не назвал» — демон версии до M3b. Без него `stop` объявил бы pid-файл
     осиротевшим ровно в том случае, ради которого его чаще всего и зовут: остановить старый
     демон, чтобы поднять новый код.
   - §5.4 говорит об отпечатке «полное содержимое записи»; `CONTEXT.md` (термин «Отпечаток») —
     «SHA-256 полей записи регистра». В плане взята формулировка `CONTEXT.md` с канонизацией
     (задача 7, шаг 7, пункт 2): расхождение между документами — дефект, а словарь проекта
     главнее.
   - §6.1 просит предупреждение у базы без секрета в `odata1c_bases`. В плане это ОТДЕЛЬНАЯ
     проверка внутри метода `bases` (задача 10, шаг 5): перечень баз клиента не создаёт вовсе, и
     без своей проверки предупреждение не появилось бы никогда.
