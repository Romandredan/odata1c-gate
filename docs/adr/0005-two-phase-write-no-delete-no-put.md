# Запись двухфазная с подтверждением в чате; `DELETE` и `PUT` отсутствуют

Подтверждение должно жить в одном окне чата, но всё, что попадает в чат, видит модель, поэтому статический пароль или «код в чате» не являются подтверждением. Выбрано: пишущие тулы возвращают превью и `pending_id`, а отдельный `odata1c_commit` помечен `anthropic/requiresUserInteraction` — Claude Code показывает диалог разрешения на каждый вызов, и этот диалог модель не контролирует. Физического удаления нет вовсе (`mark_for_deletion` = `PATCH DeletionMark`), `PUT` отсутствует, потому что затирает незаполненные реквизиты.

## Considered Options

- **Одноразовый код через TOTP/бот.** Надёжнее, но требует второго канала; пользователь отказался от любых окон вне чата.
- **Только диалог разрешения Claude Code на пишущие тулы без превью.** Пользователь подтверждал бы вслепую, не видя diff.
- **Пакетные операции.** Отложены: одна pending-операция — один объект; лимит 20 коммитов за 10 минут на сессию.

## Consequences

- Отката «из коробки» у 1С нет, поэтому демон ведёт журнал до/после в реальных значениях (локально) и даёт `undo` для `update`, `mark`, `create`, `Post`/`Unpost`.
- `commit` проверяет `DataVersion`: превью, построенное на устаревшем состоянии, не применяется.
- Остаточный риск: prompt-injection из данных 1С может склонить модель вызвать `commit` — диалог разрешения остаётся последней линией; для версий Claude Code без поддержки аннотации страхует `PreToolUse`-хук плагина.
