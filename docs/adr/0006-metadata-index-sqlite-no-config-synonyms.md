# Индекс `$metadata` в SQLite на базу; синонимы конфигурации не импортируются

`$metadata` ERP-конфигурации — десятки мегабайт, и его нельзя ни отдавать модели целиком, ни парсить на каждый запрос. Индекс на базу в SQLite (FTS5 + триграммы) даёт нечёткий поиск, валидацию полей и классификацию чувствительности; реиндекс — по требованию и по изменению sha256. В `$metadata` нет синонимов конфигурации («Реализация товаров и услуг»), только имена; нормализация + леммы pymorphy3 покрывают запросы на русском без отдельного источника синонимов.

## Considered Options

- **Импорт отчёта по конфигурации / XML-выгрузки** ради настоящих синонимов. Отвергнут пользователем: лишний ручной шаг, рассинхрон с публикацией.
- **JSON-кэш вместо SQLite.** Нет полнотекстового поиска и конкурентного доступа из нескольких сессий.

## Consequences

- Классы полей (`auto` в `policy.yaml`) пересчитываются при каждом реиндексе; ручные переопределения живут отдельно и не затираются.
- Изменение состава публикации (расширили/сократили `$metadata`) видно только после `reindex`; `404` от 1С на известную сущность даёт модели подсказку его вызвать.
