# Один `bases.yaml` на машину с паролями внутри; keyring как опция; проектных файлов нет

ADR-0007 разносил настройки на глобальный `bases.yaml` и проектный `.odata1c.yaml`, а пароли прятал в keyring. Обе меры защищали не от того, от кого защищается шлюз. Модель угроз одна: провайдер модели; диск владельца машины вне периметра по определению, и рядом с настройками лежит `journal.sqlite` с реальными значениями. Keyring при этом стоил интерактивного `init` и ручного переноса секретов при смене машины, а проектный файл дублировал реквизиты одной боевой базы по всем репозиториям. Выбрано: единственный `bases.yaml` в домашнем каталоге, закрытый правами текущего пользователя ОС, с паролями открытым текстом; `password: keyring` как необязательная альтернатива; перенос из env-файла прежнего сервера командой `odata1c base import`.

## Considered Options

- **Проектный env-файл в репозитории** (как у `1c-odata-mcp`). Привычен, но демон не знает, из какого проекта пришёл запрос, а класть путь к репозиторию в конфигурацию клиента нельзя без потери переносимости. Реквизиты одной базы копировались бы в каждый проект.
- **Формат env вместо YAML** для глобального файла. Роль, разрешения, режим гейта и путь к рецептам — вложенные структуры, в плоские `ODATA_DB_<NAME>_*` они укладываются плохо. Совместимость обеспечена импортом, а не вторым форматом.
- **Keyring по умолчанию** (ADR-0007). Отвергнуто: защита от несуществующей угрозы ценой удобства.

## Consequences

- Для команды в репозиторий уходит только запись сервера в `.mcp.json` или плагин; каждый участник описывает базы в своём `bases.yaml`. Это роль прежнего `env.example`.
- Лаунчер закрывает домашний каталог правами пользователя при создании (`icacls`, `chmod 700`); демон предупреждает, если `bases.yaml` доступен другим учётным записям.
- Секрет HMAC гейта переезжает из keyring в `daemon.yaml` (`gate_secret`) и создаётся при первом запуске.
- Смена машины — копирование домашнего каталога целиком.
