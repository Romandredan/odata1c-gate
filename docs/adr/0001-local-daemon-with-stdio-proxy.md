# Один локальный демон плюс тонкий stdio-прокси на сессию

Нужны несколько одновременных сессий Claude Code, общий индекс/словарь/журнал, один сеанс 1С на базу и приоритет проектного `.odata1c.yaml`. Единственный демон на `127.0.0.1` (MCP Streamable HTTP) даёт первые три свойства; приоритет проекта даёт stdio-прокси, потому что Claude Code выставляет `CLAUDE_PROJECT_DIR` только в окружении stdio-сервера. Прокси передаёт путь проекта заголовком и ничего больше не делает.

## Considered Options

- **Только stdio, процесс на сессию.** Просто, но N сеансов 1С (лицензии), словарь и журнал через файловые блокировки SQLite, семафор на базу между процессами — не реализуем честно.
- **Только HTTP, демон напрямую в `.mcp.json`.** Один процесс, без прокси. Но демон не знает проект вызывающей сессии: `${CLAUDE_PROJECT_DIR}` в `headers` `.mcp.json` не раскрывается (переменная живёт в окружении сервера, не Claude Code), а по подстановке env-переменных в `headers` HTTP-серверов есть открытые баги. Для plugin-серверов подстановка плейсхолдера в `headers` документирована — этот путь остаётся кандидатом на замену прокси после проверки на установленной версии (SPEC §14.1).
- **Явное имя профиля проекта в `.mcp.json`.** Работает, но требует держать имя в двух местах и не читает `.odata1c.yaml` из репозитория.

## Consequences

- Демон стартует лениво: прокси поднимает его, если порт закрыт. Windows-сервис — опция, не требование.
- Демон доверяет заголовку пути проекта только при верном локальном токене; для одного пользователя на одной машине этого достаточно.
- Claude Desktop/Cowork не выставляют `CLAUDE_PROJECT_DIR`; для них — `--project <path>` или текущий каталог.
