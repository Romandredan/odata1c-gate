# Периметр защиты — реквизиты, а не названия и ФИО

Угроза — только провайдер модели; утечка названий через промпты пользователя принята; суммы должны быть настоящими. В этих ограничениях защита названий даёт мало (связь «имя ↔ псевдоним» всё равно видна в беседе), а стоит дорого: морфология, NER для русского, подстрочный поиск, потеря знаний модели о контрагентах. Защищаются классы, которые сравниваются по равенству и выявляются формально: ИНН, КПП, ОГРН, счета, карты, СНИЛС, документы, телефоны, e-mail, даты рождения, адреса (по полям).

## Consequences

- ФИО, названия организаций, структура конфигурации, суммы, даты, графы связей видны провайдеру. Это принятый остаточный риск, а не недоработка.
- Сущности с концентрированными ПДн (`Catalog_ФизическиеЛица`, зарплатные регистры) рекомендуется не публиковать в OData или скрывать через `hide: true` в политике — минимизация сильнее любой подмены.
- NER для адресов/ФИО в свободном тексте — опция позднего этапа, не часть периметра v0.1.
