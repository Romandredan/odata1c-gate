# Список баз: глобальный `bases.yaml` плюс проектный `.odata1c.yaml` с приоритетом проекта; секреты только в keyring

Один и тот же шлюз обслуживает разные репозитории с разными наборами баз. Глобальный файл описывает все базы, проектный ограничивает видимость (`use`), задаёт `default` и может определять базы локально; одноимённая база проекта полностью замещает глобальную. Пароли 1С, HMAC-секрет гейта и токен прокси хранятся в Windows Credential Manager через `keyring`, файл с ключом `password` демон отказывается загружать.

## Considered Options

- **DPAPI-файл для секретов.** Привязан к Windows; `keyring` даёт тот же Credential Manager на Windows и Keychain/SecretService на других ОС без изменения кода.
- **Пароли в `.odata1c.yaml`.** Отвергнуто: файл лежит в репозитории.
- **OS-аутентификация в 1С.** Требует Kerberos-делегирования; отвергнута пользователем — только basic.

## Consequences

- Одна учётная запись 1С на базу: все записи в 1С будут от неё; аудит «кто изменил» — на стороне журнала демона, не 1С. Рекомендуется отдельная учётка `odata_claude` с урезанными правами и без доступа к сущностям с ПДн.
- Смена машины требует переноса секретов вручную (`odata1c secret export`).
