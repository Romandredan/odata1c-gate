# Гейт многоуровневый: реквизиты всегда, названия и ФИО по уровню базы

ADR-0003 ограничивал периметр реквизитами, потому что защита названий требовала морфологии и NER, а связь «имя в промпте ↔ псевдоним» всё равно видна провайдеру. Пересмотрено по двум причинам. Во-первых, объём утечки не одинаков: промпт называет одну организацию, а выборка отдаёт тысячу названий вместе с графом связей. Во-вторых, защита названий по полям и словарю не требует NER: `Description` и поля ФИО известных сущностей, плюс подмена уже виденных названий в свободном тексте. Уровень выбирается на базу: `off` для отладочных копий, `identifiers` для тестовых, `identifiers+names` для боевых.

## Considered Options

- **Один периметр для всех баз.** Отладочная копия получала бы токены там, где они только мешают, а боевая — открытые названия. Отвергнуто.
- **Правдоподобные подмены названий** («ООО Ромашка» вместо реального). Отвергнуто по причинам ADR-0002: правдоподобная подмена может совпасть с реальной организацией, а обратное отображение при ошибке ведёт к записи не в тот объект.
- **Читаемые метки** («Контрагент‑17») вместо единой грамматики `[[type:tail]]`. Отвергнуто: обратная подмена разбирала бы два формата, а читаемость модели не нужна; пользователю реальное имя даёт `odata1c reveal`.
- **NER для свободного текста.** Отложено в M4: качество на русском неполное, зависимости тяжёлые.

## Consequences

- Классы `org` и `person` добавлены к классам реквизитов; хвост токена для них — порядковый номер в словаре, а не HMAC, потому что нормализованного значения для сравнения между базами не требуется.
- Названия ловятся тремя слоями: `Description` сущностей из `names_for`, строковые реквизиты любой сущности по имени поля (`Руководитель`, `ФИОКассира`, `Грузополучатель`), известные значения по словарю в любой строке. Ссылочные реквизиты имени не несут: OData отдаёт `_Key`.
- Склонённые формы названий в свободном тексте не ловятся: принятый остаточный риск уровня `identifiers+names`.
- Словарь общий: значение, классифицированное в одной базе, заменяется в любой другой с уровнем выше `off`.
- Страж утечек (SPEC §6.8) становится инвариантом ответа, а не тестом: известное значение, оставшееся после гейта, заменяется до выдачи клиенту.
