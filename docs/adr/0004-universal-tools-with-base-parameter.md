# Несколько универсальных тулов с параметром `base`, а не тул на сущность или на базу

Конфигурации 1С содержат тысячи сущностей, а баз несколько; генерация тула на каждую пару убила бы контекст модели и потребовала бы перерегистрации при каждом реиндексе. Выбраны ~15 универсальных тулов (`query`, `get`, `describe_entity`, …), где база и сущность — аргументы, а знание о структуре живёт в индексе и отдаётся через `find_entity`/`describe_entity` по запросу.

## Consequences

- Точность работы модели зависит от качества `describe_entity` и server instructions; в них вкладывается больше, чем в описания тулов.
- Права на запись задаются не аннотациями отдельных тулов, а `read_only` базы и `write: deny` полей в политике.
- Tool search Claude Code работает штатно: ≤ 2 КБ на описание, короткие имена с префиксом `odata1c_`.
