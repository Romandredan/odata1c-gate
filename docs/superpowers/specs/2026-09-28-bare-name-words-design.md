# Одиночное слово в свободном тексте — не название: проект

Дата: 2026-09-28. Ветка `worktree-gate-bare-name-words`. Решение владельца 2026-09-28 (вариант 1
из двух предложенных), заменяет второй шаг Ruling 106 — список слов владельца `words.yaml`.

## 1. Задача

Слой 3 гейта (SPEC §6.5) ищет в свободном тексте ответа варианты названий организаций и ФИО,
которые словарь уже видел в полях с классом `org`/`person`, и заменяет их токенами. После
Ruling 106 название ищется только отдельным словом, но название, которое само является обычным
словом, заменяется везде: при контрагенте ООО «Мост» слово «мост» закрывается токеном в любом
комментарии, назначении платежа и тексте ошибки 1С. То же у «Вектор», «Альфа», «Сфера», у имён
(«Мария» из поля `Имя`) и фамилий, совпадающих со словами. Это порча данных, не защищающая ничего
секретного.

Владелец отказался от ручного списка таких слов (`words.yaml`, решение 2026-09-24) в пользу общего
правила: **одиночное слово без формы собственности и без кавычек названием в свободном тексте не
считается.** Правило касается только уровня `identifiers+names`: реквизиты (ИНН, ОГРН, счета и
другие) детекторы ищут в тексте как прежде.

## 2. Критерий готовности

1. В свободном тексте голое одиночное слово, совпавшее с названием или частью ФИО, не заменяется.
2. Закрываются по-прежнему: название с формой собственности (ООО «Мост», ООО Мост), в кавычках
   («Мост», "Мост"), название из нескольких слов (Торговый дом Вектор), название с цифрами или
   дефисом (Альфа-Банк, 1С-Рарус), полное ФИО и любые значения в полях с классом `org`/`person`.
3. Слой раскрытого значения (Ruling 25, 27) не меняется: значение, которое шлюз подставил в запрос
   к 1С по токену модели, закрывается в ответе в любом написании, как сейчас.
4. Все тесты, `ruff`; приёмка на живой базе `trade_dev` показывает, сколько замен «отдельным
   словом» ушло и что среди оставшихся нет голых одиночных слов; ревью атакующим.

## 3. Решение

### 3.1 Правило ключей поиска

Ключи поиска (варианты названия) строит одна функция — `dictionary.name_variants_of`. Сейчас из
значения получаются ключи «как есть» и «без формы собственности»; для ядра без букв (`ООО "2020"`)
голое ядро уже заменено ядром в кавычках и формами со своей формой собственности (Р3-2).

Новое правило обобщает этот приём. **Одиночное слово** — ключ из одних букв без пробелов, дефисов,
цифр и прочих знаков (`^[^\W\d_]+$` после нормализации). Для такого ключа голое написание в поиск
не идёт; вместо него — узнаваемые написания:

| Значение в поле | Ключи сейчас | Ключи по новому правилу |
|---|---|---|
| `ООО "Мост"` | `ооо "мост"`, `мост` | `ооо "мост"`, `"мост"`, `ооо мост`, `ооо"мост"` |
| `Мост` (без формы) | `мост` | `"мост"` |
| `ООО "Торговый дом Вектор"` | `ооо "торговый дом вектор"`, `торговый дом вектор` | без изменений |
| `Альфа-Банк` | `альфа-банк` | без изменений (не одиночное слово: дефис) |
| `Иванов Иван Иванович` | `иванов иван иванович` | без изменений |
| `Мария` (поле `Имя`) | `мария` | `"мария"` |

Форма собственности — только своя, из самого значения (`ФОРМЫ`), как у ядра без букв: чужая форма
скорее означает другое юрлицо. Минимальная длина ключа (`МИНИМАЛЬНАЯ_ДЛИНА_ВАРИАНТА`) и граница
слова (Ruling 106) действуют как прежде.

Почему «одно слово из букв», а не «слово из словаря русского языка»: словаря языка в поставке нет,
а собственное название из одного слова («Ромашка», «Мост», «Сфера») почти всегда совпадает с
обычным словом или именем. Название с дефисом, цифрой, латиницей вперемешку с кириллицей или из
нескольких слов в обычном тексте случайно не встречается.

### 3.2 Где действует

Одна правка в `name_variants_of` доходит до всех потребителей ключей: маскировщика (слой 3,
`Masker._заменить_известные_названия`), стража (`Guard`, автомат названий) и ключей, которые
пополняет ранний проход (`add_scrubbed_name_variant` — там ключ длиннее одного слова по построению
и правило его не касается). Слой раскрытого (`revealed.py`) строит написания из значений, раскрытых
в этом вызове, а не из словаря, и не меняется (критерий 3).

### 3.3 Словари, заполненные прежними версиями

Ключи хранятся в таблице `name_variants`. `ВЕРСИЯ_СХЕМЫ` поднимается с 3 до 4: при первом открытии
словаря новой версией `_пересчитать_названия` строит ключи всех токенов `org`/`person` заново тем же
`name_variants_of` — механизм уже есть (переход на версии 2 и 3). Токены, написания в журнале и
раскрытие не меняются: пересчитываются только ключи поиска.

### 3.4 Поправка итогового ревью ветки (2026-09-28)

Таблица выше — первоначальный проект; реализация дополнила её по итогам ревью.

- Одиночным словом считается слово из букв **одной** письменности (находка I-1): у `ТехноNIKOL`,
  `ВкусVill` голый ключ остаётся, как и обещал довод выше про латиницу вперемешку с кириллицей.
- Ключ с одной открывающей кавычкой (`"мост`) добавлен при реализации (1С обрезает строку без
  закрывающей «ёлочки»).
- Одиночное слово от четырёх символов получает ключи частых написаний, которые до ветки закрывал
  голый ключ (находка C-1): апострофы (прямой, типографский, правый с обеих сторон), только
  закрывающая кавычка, пробел внутри кавычек, своя форма через точку и дефис, латинский двойник своей формы (`OOO`, `AO`) и
  полная запись своей формы. Итог — 22 ключа у `ООО "Мост"`, 11 у `Мост` (SPEC §6.5).
  `ВЕРСИЯ_СХЕМЫ` поднята до 5.
- Редкие написания открыты и названы «Остатком Ruling 115» (SPEC §6.5): угловые кавычки, обратный
  апостроф, чужая форма, общее написание двух токенов одного ядра.

## 4. Цена

- Одиночное название без кавычек и формы в тексте остаётся открытым: «отгрузили Мосту», «заказ
  Ромашки», «Ромашка просит отсрочку». Склонённые формы открыты и сейчас (Ruling 106); открывается
  именительный падеж без кавычек.
- Редкие написания одиночного слова открыты — «Остаток Ruling 115» (раздел 3.4).
- Фамилия или имя одним словом в тексте открыты («передал Иванову», «звонила Мария»); полное ФИО
  закрыто. Написание с инициалами («Иванов И.И.») закрыто, только если словарь видел его в поле.
- Строка «Гейт открывает» в описании выпуска `0.3.0`: одиночные названия и части ФИО в свободном
  тексте на уровне `identifiers+names`.

## 5. Проверки

- Юнит: ключи `name_variants_of` по таблице раздела 3.1; маскировщик и страж не заменяют голое
  одиночное слово и заменяют его в кавычках, с формой, в составе полного названия; значения в
  полях с классом заменяются как прежде; пересчёт ключей при переходе версии 3 → 4.
- Существующие тесты, где голое одиночное слово в тексте ожидалось закрытым, переписываются под
  правило с ссылкой на Ruling 115; тесты с многословными названиями не меняются.
- Property-тесты («прямая + обратная подмена = тождество», «страж не пропускает значения словаря»)
  с генератором названий: на одиночных словах — проверка по новому правилу.
- Живая приёмка — `tools/probes/word_boundary_live_check.py` на `trade_dev` до и после (`--src`):
  число токенов `org`/`person` отдельным словом в свободном тексте и форма исходного слова в каждом
  случае, ушедшем из замены (печатается форма, не значение). Ожидание: ушли только одиночные слова.
- Ревью атакующим по диффу: поиск написания, при котором настоящее название организации или ФИО
  проходит открытым сверх цены раздела 4.

## 6. Документы

## 7. Вне проекта

Список слов владельца `words.yaml` и команды `odata1c words …` — не делаются. Поиск склонённых
форм — нет (Ruling 106 остаётся в силе).
