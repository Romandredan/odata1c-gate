# Плагин для ZCode

Плагин `odata1c` работает в ZCode: модель получает те же девять тулов чтения и семь тулов записи
MCP-шлюза, четыре навыка и агента-следователя, что и плагин Claude Code. Формат плагина и
маркетплейсов у ZCode тот же, что в Claude Code, и файлы навыков, агента и MCP-конфигурации —
те же самые (`plugin/`); отдельной копии под ZCode нет намеренно, по той же причине, что и для
OpenCode (`docs/OPENCODE.md`): копии расходятся при первой правке, и расходятся молча.

## Подключение

Требуются ZCode и установленная командная строка владельца:

```sh
uv tool install odata1c-gate
```

Плагины в ZCode ставятся в менеджере плагинов: добавьте маркетплейс — GitHub-репозиторий
`Romandredan/odata1c-gate` («Настройки» → «Плагины» → «Create» → «Add marketplace») — и установите
плагин `odata1c`; порядок описан в документации плагинов
[ZCode](https://zcode.z.ai/en/docs/plugin). Базы подключаются той же командной строкой, что и без
ZCode (`uvx --from odata1c-gate odata1c base add …`, `reindex …`): разделы README «Быстрый старт»
и [docs/install.md](install.md). Навык `odata1c-setup` ведёт модель по подключению базы диалогом,
пароль модель не видит.

## Ручной шаг: модель агента

Файл агента `odata1c-investigator` несёт `model: haiku` в frontmatter — имя модели Claude Code.
ZCode его не разрешает, и по умолчанию следователь работает на модели сессии: описание обещает
дешёвого агента, а стоимость определяет сессия. Закрепить дешёвую модель — создать глобального
агента ZCode: скопируйте файл агента из репозитория
([plugin/agents/odata1c-investigator.md](https://github.com/Romandredan/odata1c-gate/blob/main/plugin/agents/odata1c-investigator.md))
в `~/.zcode/agents/odata1c-investigator.md` и замените строку `model:` на селектор из списка
моделей вашего хоста. Суффикс уровня reasoning обязателен — селектор без него не запускается:

```yaml
model: "account:<план>/<модель>$<уровень>"
# пример: account:zai-individual-coding-plan/GLM-5.3-Flash$low
```

Для механического следователя достаточен низкий уровень. Строку `tools:` оставьте как есть — она
перечисляет тула обеих форм регистрации MCP-сервера (`mcp__plugin_odata1c_gate__odata1c_*` для
плагинной и `mcp__odata1c__odata1c_*` для ручной), и она же исключает тула записи: агент остаётся
только для чтения. Глобальный агент виден в сессии под именем `odata1c-investigator` рядом с
плагинным (`odata1c:odata1c-investigator`); правка определения подхватывается новой сессией.

## Подтверждение записи и защита каталога шлюза

Хук `PreToolUse` плагина выполняется в ZCode. Правила защиты домашнего каталога шлюза
(`bases.yaml` с паролем 1С, `daemon.yaml`, `launcher.key`, `gate.sqlite`, `journal.sqlite`)
отклоняют чтение и правку этих файлов моделью; те же правила требуют подтверждения человека на
тул `odata1c_commit`, и отказ в вопросе ничего не пишет. Двухфазная запись — превью,
подтверждение, журнал, откат — описана в README и работает одинаково во всех клиентах.

По умолчанию запись в ZCode недоступна: демон видит, что лаунчер запущен не исполняемым файлом
Claude Code, и без настройки не доверяет клиенту — `odata1c_commit` отвечает
`write_unsupported_client`, в 1С не уходит ничего (проверено пробой 2026-11-10 в живой базе).
Подтверждением остаётся диалог клиента, поэтому поднимите `write_confirm_fallback` в `daemon.yaml`
до `trust_client`, как для OpenCode (`docs/OPENCODE.md`, раздел «Подтверждение записи»); если
после правки коммит всё ещё отказывает, перезапустите демон (`odata1c daemon stop`, лаунчер
поднимет его заново). Механизм подтверждения в записи журнала при этом отличим от Claude Code —
сравните новую запись журнала с прежними, где механизм `claude_code`.
