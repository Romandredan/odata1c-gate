## Удобство владельца

- **`odata1c base set <база> --gate <уровень> --write on|off`** — менять уровень гейта и
  возможность записи из командной строки, без ручной правки `bases.yaml`. Файл перечитывается
  демоном на лету, так что команда действует без перезапуска; проверяет значения, сохраняет
  комментарии. Туда же просятся `--label` и `--role`. (Предложено владельцем 2026-09-21.)
- **Правка контактов и даты рождения со слов пользователя через `odata1c_update`.** Сейчас
  открытое значение в поле класса `contact`/`dob` отклоняется — иначе ответ «изменений нет»
  позволял бы подбирать чужие данные. Вариант без оракула: для таких полей не сравнивать с
  текущим значением и всегда готовить запись. Полдня работы и одно ревью.
- **Пояснение для модели** в теме `odata1c_info("write_protocol")` и навыке `odata1c`: почему
  открытый телефон или дата рождения в `update` отклоняются и что делать (токен или `create`).

## Запись

- **`Edm.Int64`**: 1С молча не пишет значение у единственного проверенного поля (проба
  `docs/probes/P9-write-forms.md` вывода не дала) — нужен объект с таким полем без собственной
  логики конфигурации.
- **Периодические независимые регистры** проверены только на заглушке — нужна живая проверка на
  базе, где есть безопасный регистр рядом с объектом-маркером.
- **Действия документов, кроме `Post`/`Unpost`**; пакетные операции; запись регистров с
  регистратором — закрыты намеренно, открывать по отдельному решению.
- **Предел числа подготовок на сессию** (защита в глубину от перебора через превью).
- Мелочи ревью хвостов записи: откат молча отбрасывает поле строки, которого нет в индексе (у
  полей шапки — отказ); неточный докстринг `_строки_отката`; подсказка неизвестного исхода в
  константе `_ПОДСКАЗКА_НЕИЗВЕСТНОГО`.

## Гейт и конфигурации

- **База БП** (`bp_test`, подключена 2026-09-24): правила гейта, живая приёмка и рецепты `bp.yaml`
  сделаны (ADR-0016, `docs/probes/BP-recon.md`, `docs/probes/BP-live-check.md`). В тестовой базе
  нет кадровых данных: правила паспорта, адресов работников, СНИЛС под именем `СтраховойНомерПФР`
  и текста зарплатной карты на данных не проверены — нужна база с зарплатой (ЗУП или БП).
  Шаблон рецептов ЗУП — ждёт базы.
- Команда конструктора для каталога правил владельца (`<дом>/gate/*.yaml`) — пока файл пишется
  руками по шапке каталога поставки.
- Названия складов открыты по умолчанию — решение владельца; закрывается строкой `names_for`.
- Остаточная цена ключа с заглушкой: две организации с одинаковым названием и разными ИНН могут
  получить один токен в свободном тексте, пока словарь не выучит обе.
- Ключ с одной открывающей кавычкой у безбуквенного ядра (`"2020` при обрезанной строке) — тот же
  разрыв, что закрыл Ruling 115 для одиночного слова.

## Рецепты и политика

- **`expand` в рецептах** — названия вместо ключей в ответах шаблонных отчётов.
- **Наборы рецептов по конфигурациям как пополняемая часть плагина.**
- **`policy custom` и `policy copy`** — свой класс по регулярному выражению и перенос политики
  между базами одной конфигурации.

## Эксплуатация и код

- **Разрезать `src/odata1c/write/service.py`** (3500+ строк) по операциям — главный источник
  стоимости работы агентов над записью; карта кода `tools/code_map.py` помогает мало.
- `daemon stop` по осиротевшему pid-файлу может снять чужой процесс; два одновременных
  реиндекса одной базы пишут один временный файл.

- Служба Windows для демона; восстановление сессии после смерти демона.
