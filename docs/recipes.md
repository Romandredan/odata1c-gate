# Рецепты

Рецепт — именованный запрос с параметрами к одной сущности базы: «остатки на складе», «долги
клиентов». Вместо того чтобы модель каждый раз собирала OData-запрос заново и рисковала ошибиться
в имени регистра или поля, она вызывает готовый рецепт с нужными значениями параметров.

Зачем: один и тот же вопрос — один и тот же проверенный запрос, а не заново собранный каждый раз;
общий язык между пользователем и моделью — «покажи остатки по складу такому-то» сразу становится
рецептом, а не разбором структуры базы.

Как пользоваться: модель вызывает `odata1c_recipe` без имени — получает список рецептов базы с
параметрами, с именем и параметрами — выполняет рецепт. Пользователю достаточно попросить обычным
языком: «покажи остатки по складу Основной на сегодня».

Откуда берутся рецепты — три слоя, сильный побеждает по имени целиком:

1. **Файл базы** (`bases/<база>/recipes.yaml`) — свои рецепты именно этой базы.
2. **Библиотека конфигурации** (`~/.claude/odata1c/recipes/<config>/<имя>.yaml`, один рецепт —
   один файл) — общая для всех баз одной конфигурации 1С; какая это конфигурация, называет поле
   `config` записи базы (`ut`, `bp`, `zup` или свой код).
3. **Шаблон поставки** — стартовый набор рецептов для типовой конфигурации, его кладёт
   `odata1c base add --recipes ut|bp|zup`.

Как пополнять библиотеку: в конце удачной задачи модель может свернуть запрос в рецепт — по
просьбе «сохрани как рецепт» — навыком плагина `odata1c-recipe`. Готовый файл проверяется командой
`odata1c recipe check <config>`, а `odata1c recipe list <база>` показывает рецепты базы вместе с
источником каждого (файл базы, библиотека или шаблон).

Файл одного рецепта — обычный YAML, без значений и токенов базы, только имена полей и параметры:

```yaml
title: Остатки по складу
description: Количество в наличии на указанный момент.
entity: AccumulationRegister_ТоварыНаСкладах_Balance
params:
  period: { type: datetime, required: true, description: момент остатков }
  warehouse: { type: guid, required: false, description: Ref_Key склада }
virtual:
  Period: "{period}"
  Condition:
    - Склад_Key eq {warehouse}
select: [Номенклатура_Key, ВНаличииBalance]
filter: ВНаличииBalance gt 0
top: 200
```

В рецепте не хранятся ни значения, ни токены — только структура запроса и объявленные параметры;
конкретные `Ref_Key`, даты и суммы модель подставляет при вызове.

Библиотека рассчитана на пополнение по ходу работы, а не на разовую поставку: в планах — готовые
наборы рецептов по типовым конфигурациям как пополняемая часть плагина.
