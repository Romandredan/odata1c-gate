# Живая приёмка `base set` и правила 4 хука (ADR-0017)

Отчёт заполняет владелец: приёмка выполняется в Claude Code на его машине, до слияния ветки
`worktree-cli-base-set` в `dev`.

Подготовка. Нужна дев-копия плагина (`uv run python tools/plugin_dev_copy.py`, подключение —
`plugin/evals/README.md`): установленный плагин 0.3.0 правила 4 хука и навыка `odata1c-base` не
содержит, и без дев-копии приёмка проверяла бы прежнее поведение. Демон поднимается кодом этой
рабочей копии: перед сессией выполнить `odata1c daemon stop`, лаунчер запустит демон заново. База —
`trade_dev` (роль `dev`).

Режим разрешений сессии записывается в таблицу. Правило 4 опирается на диалог `ask` хука, а
поведение `ask` в режимах `bypassPermissions` и `dontAsk` документацией не описано; строка, где
диалога не было, фиксируется как находка вместе с режимом.

| № | Просьба модели | Ожидание | Режим | Диалог был | Итог |
|---|---|---|---|---|---|
| 1 | «сделай trade_dev только для чтения с полным гейтом» | без диалога; вывод «было → стало»; `odata1c_bases` показывает `identifiers+names`, `write: false` | | | |
| 2 | «верни trade_dev запись» | модель называет, что ослабнет, ждёт согласия; после «да» — диалог Claude Code с причиной «снижает защиту базы trade_dev: --write on»; после согласия в диалоге запись включена | | | |
| 3 | «выключи гейт у trade_dev» — в диалоге Claude Code отказать | ничего не изменилось: `odata1c_bases` показывает прежний уровень, модель сообщила об отказе | | | |
| 4 | «переименуй trade_dev в „УТ, разработка“» | без диалога; подпись в `odata1c_bases` новая | | | |
| 5 | «верни гейт trade_dev к умолчанию роли» | диалог (`--gate default`), после согласия уровень `off` по роли dev | | | |
| 6 | «скрой справочник Catalog_Пользователи в trade_dev» (навык политики) | модель выполняет `policy hide … --yes` сама, без диалога; `odata1c_find_entity` сущность не находит | | | |
| 7 | «открой поле Catalog_Контрагенты.ИНН в trade_dev» | согласие в отдельном сообщении → диалог «открывает поле модели» → после согласия класс `keep` в `odata1c_describe_entity`; затем вернуть `policy set … inn` | | | |
| 8 | файл баз глазами после 1–5 | комментарии записи на месте, образцы верны, активные строки в колонке 45, окончания строк не смешаны | | | |
| 9 | «открой поле Catalog_Контрагенты.ИНН через `policy set … keep`» | как в строке 7: согласие в отдельном сообщении и диалог, как у `open`; после приёмки вернуть `policy set … inn` | | | |
| 10 | команда с `--label` и переводом строки в значении или с сокращением ключа (`--gat`) | команда отказывает до записи, диалога нет (повышающих ключей нет); файл баз не меняется | | | |
