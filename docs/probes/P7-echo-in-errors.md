# P7 — эхо переданных значений в ошибках 1С

**Дата:** 2026-09-11. **База:** `trade_dev` (УТ 11, платформа 8.3, публикация за IIS).
**Зачем:** ревью задачи N1 плана M1d утверждало, что 1С повторяет литералы отбора в тексте ошибки,
и через это раскрытое гейтом значение возвращается модели. Более ранняя проверка оркестратора
(2026-09-10) показывала обратное. Проба разрешает расхождение фактом.

**Метод:** в запрос подставляется заведомо отсутствующее в базе значение-метка (`ZZMARKER7391`,
для дат — `1917-11-07T00:00:00`); в ответе ищется сама метка. Появление метки означает эхо, а не
данные. Скрипты: `scratchpad/live_echo_probe.py` сессии c91a3296.

## Результат: эхо существует, но не везде

| Форма запроса | HTTP | Эхо |
|---|---|---|
| `$filter`: строковый литерал по несуществующему полю | 400 | нет |
| `$filter`: незакрытая кавычка в литерале | 400 | нет |
| `$filter`: **число без кавычек** | 400 | **да** |
| `$filter`: функция над неподходящим полем | 500 | нет |
| `$filter`: неподдерживаемый оператор | 400 | нет |
| `$filter`: `datetime'…'` по несуществующему полю | 400 | нет |
| `$filter`: `datetime'…'` по строковому полю | 200 | нет |
| `$filter`: битый `datetime'…'` | 400 | нет |
| **`$orderby`** — имя | 400 | **да** |
| **`$select`** — имя | 400 | **да** |
| **`$expand`** — имя | 400 | **да** |
| **Ключ-строка** `Catalog_X(guid'…')` | 400 | **да** |
| **Имя набора** `Catalog_<метка>` | 404 | **да** |
| Сегмент пути после набора | 400 | нет |

## Выводы

1. **Прежний вывод оркестратора был верен, но узок.** «1С не повторяет литералы» справедливо
   ровно для строкового и `datetime`-литерала в `$filter` — самой частой формы. Обобщение на все
   ошибки платформы оказалось неверным: имена в `$select`/`$orderby`/`$expand`, строковый ключ,
   имя набора и **число без кавычек в `$filter`** возвращаются в тексте ошибки дословно.
2. **Находка N1 обоснована.** Значение, раскрытое гейтом и ушедшее в 1С не строковым литералом
   `$filter`, а ключом — возвращается в ошибке. Обратная замена раскрытого (Ruling 25) обязана
   работать независимо от формы: набор форм платформы шире, чем проверяет любая одна проба, и
   зависит от версии и публикации.
3. **Решение по классу `dob` (Ruling 7) остаётся в силе:** `datetime'…'` не отражается ни в одной
   из четырёх проверенных форм. Основание того решения подтвердилось именно в своих границах.
4. **Общее правило проекта:** поведение платформы — не рубеж обороны. Проба говорит, что эхо есть
   сегодня в шести формах из четырнадцати; завтра на другой публикации их может быть больше.
   Инвариант 1 держится собственными средствами шлюза, а не тем, что «платформа обычно молчит».

## Оговорка о ложном срабатывании

Случай «`datetime` в `$orderby`» сначала показал эхо при HTTP 200 — метка «1917» нашлась в
шестнадцатеричном `Ref_Key` записи. Это артефакт поиска по подстроке, а не эхо: запрос прошёл
успешно, ошибки не было. Для дат метка-число плохо подходит; в остальных случаях метка буквенная
и такого пересечения не даёт.
