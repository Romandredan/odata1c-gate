# odata1c-gate

Локальный MCP-шлюз между агентами (Claude Code и совместимые) и стандартным OData-интерфейсом
1С:Предприятие 8.3. Между моделью и 1С стоит гейт псевдонимизации: реквизиты (ИНН, счета,
паспорта, телефоны) и, на выбранном уровне, названия организаций и ФИО заменяются токенами вида
`[[type:tail]]` до того, как данные увидит модель. Обратная подмена происходит только внутри
гейта перед отправкой запроса в 1С.

Один пользователь, одна машина, несколько сессий агентов одновременно, несколько баз 1С.

**Статус: чтение закрыто (M1), запись реализована (M2).** Готовы настройки и реестр баз, клиент
1С, индекс метаданных, гейт и слой MCP: демон, лаунчер, девять тулов чтения и семь тулов записи.
Приёмка чтения на реальной базе УТ пройдена ([docs/probes/M1d-live-check.md](docs/probes/M1d-live-check.md)).
Запись двухфазная: тул готовит операцию и показывает превью в токенах, выполняет её только
`odata1c_commit` после подтверждения пользователя в клиенте, каждая запись откатывается
`odata1c_undo`; приёмка записи на живой базе пройдена скриптом и вручную в Claude Code, этап M2
закрыт ([docs/probes/M2-live-check.md](docs/probes/M2-live-check.md)). Впереди: M3 package → M4
сетевая публикация (SPEC §13).

## Как подключить

Нужны Python 3.12 или новее и менеджер окружения [`uv`](https://docs.astral.sh/uv/). Пока пакет
не опубликован, команды запускаются из рабочей копии — `uv sync`, затем:

```bash
uv run odata1c init                                   # ~/.claude/odata1c/ с шаблонами настроек
uv run odata1c base add trade_dev --role dev --recipes ut   # спросит адрес, пользователя, пароль
uv run odata1c base test trade_dev                    # проверить соединение с 1С
uv run odata1c reindex trade_dev                      # построить индекс метаданных по $metadata
```

Адрес базы — это адрес публикации OData 1С, он оканчивается на `/odata/standard.odata/`. Роль
задаёт, насколько строго работает гейт и что разрешено: `prod` — названия и реквизиты скрыты,
только чтение; `test` — скрыты реквизиты; `dev` — гейт выключен. Пароль ложится в
`~/.claude/odata1c/bases.yaml` открытым текстом, файл закрывается правами владельца (ADR-0014).

Подключение к Claude Code — строка в `.mcp.json` проекта:

```json
{ "mcpServers": {
    "odata1c": { "command": "uv", "args": ["run", "odata1c", "mcp"] } } }
```

`odata1c mcp` — тонкий процесс на сессию: он сам поднимает общий демон (`odata1c daemon`,
`127.0.0.1:7171`) и проксирует ему вызовы. После перезапуска Claude Code модели становятся видны
тулы `odata1c_bases`, `odata1c_find_entity`, `odata1c_describe_entity`, `odata1c_query`,
`odata1c_get`, `odata1c_info`, `odata1c_reindex`, `odata1c_raw_get`, `odata1c_recipe`. Начинать
разговор стоит с `odata1c_bases` — тул перечислит видимые базы и режим гейта у каждой. Рядом —
тулы записи `odata1c_create`, `odata1c_update`, `odata1c_mark_for_deletion`, `odata1c_action`,
`odata1c_undo`, `odata1c_commit`, `odata1c_journal`; пишут они только в базу с `write: true` в
`bases.yaml` (по умолчанию у ролей `test` и `dev`), в прочие — отказ `base_read_only`.

Реальное значение за токеном можно посмотреть только самому, мимо модели:
`uv run odata1c reveal "[[inn:M4T2Q9XZ7K]]"`.

Подробности — «Запуск и подключение к Claude Code» в [AGENTS.md](AGENTS.md).

## Структура репозитория

```text
src/odata1c/          пакет PyPI: демон, лаунчер, CLI (SPEC §2.2, §11.1)
  config/             bases.yaml и daemon.yaml, роли, валидация, права файлов
  registry/           реестр баз, статус индекса, видимость по сессии
  client1c/           httpx-пул на базу, IBSession, семафор, маппинг ошибок 1С
  index/              парсер EDMX → metadata.sqlite, реиндекс, нечёткий поиск
  gate/               детекторы реквизитов, словарь, подмена в обе стороны, страж
  write/              разрешения, pending-операции, commit, журнал, undo
  recipes/            загрузка рецептов и рендеринг параметров в OData-литералы
  tools/              регистрация тулов, ресурсов, промптов, server instructions
  templates/          файлы-шаблоны в поставке: конфигурация и рецепты УТ/БП/ЗУП
  cli.py              команды odata1c: init, base, reindex, policy, reveal, daemon, mcp
  daemon.py           демон: тулы, ресурсы, промпт, MCP Streamable HTTP на 127.0.0.1
  launcher.py         лаунчер: stdio-прокси демону, подъём демона, проброс elicitation
plugin/               плагин Claude Code: навык, хук, агент (SPEC §11.2)
tests/                unit / property / integration / evals + образцы EDMX (SPEC §12)
tools/probes/         скрипты технических проверок и приёмки на живой базе
docs/adr/             архитектурные решения
docs/probes/          отчёты проверок P1–P7 и приёмки M1d
```

## Что не попадает в репозиторий

`bases.yaml` хранит пароли 1С открытым текстом (SPEC §3.4), поэтому в git не коммитятся
конфигурация рабочей машины, env-файлы, базы SQLite (словарь, индекс, журнал), выгрузки
`$metadata` и логи — см. [.gitignore](.gitignore). В поставке живут только файлы-шаблоны
в `src/odata1c/templates/`, в тестах — урезанные образцы `$metadata`, не полные дампы.
