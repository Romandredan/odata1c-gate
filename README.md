# odata1c-gate

**Claude Code работает с живой базой 1С — и не видит ни одного ИНН, счёта, телефона или названия
клиента.**

odata1c-gate — локальный MCP-шлюз к стандартному OData-интерфейсу 1С:Предприятие 8.3. Между
моделью и базой стоит гейт псевдонимизации: защищаемые значения заменяются токенами до того, как
попадут в контекст модели, и подставляются обратно только внутри шлюза, перед запросом в 1С.

```text
Вы:      покажи пять последних заказов любого клиента

Claude:  Клиент [[org:16]], ИНН [[inn:M4T2Q9XZ7K]]

         № заказа      дата          сумма
         ТД-004512     12.09.2026    184 300,00
         ТД-004498     10.09.2026     52 710,00
         …
```

Номера, даты и суммы — как в базе. Название и ИНН — токены: одно значение всегда даёт один и тот
же токен, поэтому по нему можно искать, связывать документы и продолжать разговор. Настоящее
значение видите только вы — командой `odata1c reveal` в своём терминале, мимо модели.

## Зачем это

Дать модели читать рабочую базу 1С — значит отдать ей персональные данные и коммерческую тайну:
ИНН контрагентов, расчётные счета, телефоны и адреса физических лиц, названия клиентов.
Обезличивать выгрузку заранее не всегда удобно (модель должна видеть свежие данные и уметь
дозапрашивать их при необходимости), а инструктировать модель «не показывай ИНН» бессмысленно:
инструкция — не механизм, да и провайдер модели всё равно увидит даже то, что не было «показано»
пользователю.

Шлюз решает это подменой на границе: реальные значения просто не покидают вашу машину.

## Возможности

- **Чтение любой базы 1С с публикацией OData**: справочники, документы, регистры, остатки и
  обороты — обычными вопросами в чате. Модель сама находит нужные объекты по названию.
- **Три уровня защиты на выбор для каждой базы**: выключено, только реквизиты (ИНН, КПП, счета,
  паспорта, СНИЛС, телефоны, почта, адреса, даты рождения), реквизиты плюс названия организаций
  и ФИО. Что именно скрывать, настраивается до отдельного поля.
- **Страж утечек**: последний проход по каждому готовому ответу — включая тексты ошибок 1С.
- **Запись с подтверждением**: создание и изменение объектов, проведение документов, пометка
  удаления, записи регистров сведений. Модель только готовит операцию и показывает, что
  изменится; в 1С она уходит после вашего подтверждения в диалоге Claude Code. Каждая запись
  попадает в журнал и откатывается.
- **Рецепты** — готовые именованные запросы («остатки на складе», «долги клиентов»), которые
  пополняются по ходу работы.
- **Несколько баз и несколько сессий одновременно**, всё локально: шлюз слушает только
  `127.0.0.1`, пароль 1С модели недоступен.

## Инструменты модели

Семнадцать инструментов MCP — их вызывает сама модель, вам достаточно задать вопрос.

**Чтение**

| Инструмент | Что делает |
|---|---|
| `odata1c_bases` | какие базы доступны: подпись, роль, уровень защиты, состояние индекса |
| `odata1c_find_entity` | найти справочник, документ или регистр по названию, когда точное имя неизвестно |
| `odata1c_describe_entity` | состав объекта: поля, типы, ключи, связи и какие поля защищены |
| `odata1c_query` | выборка записей: отбор, сортировка, страницы — основной способ читать данные |
| `odata1c_get` | один объект по ключу |
| `odata1c_recipe` | готовые запросы базы: перечень или выполнение одного — остатки, долги, продажи |
| `odata1c_raw_get` | произвольный запрос к публикации, когда остальных инструментов не хватает |
| `odata1c_info` | встроенный справочник для модели: устройство OData 1С, токены, порядок записи |
| `odata1c_reindex` | обновить индекс метаданных после изменения конфигурации 1С |

**Запись** — каждый инструмент только готовит операцию и показывает, что изменится; в 1С её
отправляет `odata1c_commit` после вашего подтверждения.

| Инструмент | Что делает |
|---|---|
| `odata1c_create` | создать элемент справочника, документ или запись регистра сведений |
| `odata1c_update` | изменить реквизиты объекта или состав строк его табличной части |
| `odata1c_action` | провести документ или отменить проведение |
| `odata1c_mark_for_deletion` | поставить или снять пометку удаления |
| `odata1c_delete_record` | удалить запись независимого регистра сведений |
| `odata1c_commit` | выполнить подготовленную операцию — только после подтверждения в диалоге Claude Code |
| `odata1c_undo` | откатить выполненную запись по журналу |
| `odata1c_journal` | история записей: что, когда и как было подтверждено |

Плюс три навыка (методика работы с базой, настройка защиты, сохранение рецептов) и агент для
сбора фактов из базы только чтением.

## Установка

Нужны [`uv`](https://docs.astral.sh/uv/) и Claude Code.

```text
claude plugin marketplace add Romandredan/odata1c-gate
claude plugin install odata1c@odata1c-gate
uv tool install odata1c-gate
```

Первые две команды ставят плагин Claude Code, третья — команду `odata1c` для вашего терминала.

## Сразу после установки

Подключите базу — понадобятся адрес публикации OData, пользователь 1С и пароль:

```text
odata1c init
odata1c base add ut_test --role test --recipes ut
odata1c base test ut_test
odata1c reindex ut_test
```

`base add` спросит адрес (он оканчивается на `/odata/standard.odata/`), подпись базы, пользователя
и пароль. Роль задаёт стартовые настройки: `prod` — максимальная защита и только чтение, `test` —
защита реквизитов и запись, `dev` — без защиты. Первый `reindex` на типовой конфигурации идёт
несколько минут.

Теперь спрашивайте в Claude Code:

- «какие базы 1С мне доступны?»
- «найди справочник контрагентов и покажи, какие поля в нём защищены»
- «возьми любого контрагента и покажи его пять последних заказов»

Если что-то не работает — `odata1c doctor` покажет, где именно.

## Ограничения

- Проверено с Claude Code. Другие клиенты MCP подключаются и читают, но запись в них по
  умолчанию выключена, а навыки и агент плагина недоступны.
- Узнаваемое сокращение названия клиента в свободном тексте («…отгрузка в ЦСКА…») может пройти
  открытым: шлюз знает полные написания названий, а не их разговорные формы.
- Объекты 1С не удаляются физически — только пометка удаления.
- Шаблоны рецептов из поставки заполнены для «Управления торговлей»; для других конфигураций
  библиотека пополняется по ходу работы.

Полный перечень — в разделе [«Что защищено»](docs/security.md).
