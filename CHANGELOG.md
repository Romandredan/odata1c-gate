# Изменения

Формат — по [Keep a Changelog](https://keepachangelog.com/ru/1.1.0/), нумерация —
[семантическая](https://semver.org/lang/ru/). Даты в формате ГГГГ-ММ-ДД.

## Не выпущено

Хвосты записи (2026-09-20): проба `docs/probes/P9-write-forms.md`, приёмка на живой базе
`docs/probes/M3b-live-check.md`.

### Added

- Запись **независимых регистров сведений**: `odata1c_create` и `odata1c_update` записи по полному
  ключу, новый тул `odata1c_delete_record` (по разрешению `independent_register_delete`), откат
  каждой операции. Создание по существующему ключу — отказ `record_exists`. Регистры, подчинённые
  регистратору, по-прежнему закрыты.
- **Табличные части в `odata1c_update`**: модель передаёт часть целиком, превью показывает разницу
  по строкам, откат возвращает прежний состав строк.
- `tools/code_map.py` — карта кода по подпакетам для агентов.

### Changed

- `LineNumber` строк табличной части шлюз проставляет сам (или требует ровно 1..n): без номеров
  1С отвечала HTTP 500 уже после подтверждения.
- Открытый литерал в поле класса `contact`/`dob` у `odata1c_update` отклоняется и в строках
  табличных частей, как в полях шапки (закрыт канал подбора значения по ответу «изменений нет»).

## 0.1.1 — 2026-09-20

Хвосты и остатки этапов M1d–M3 (этап M3b, сокращённый состав — решение владельца, Ruling 100, 101).

### Fixed

- Название рядом со своим токеном в одном ответе гейта больше не остаётся открытым: маскировка
  ответа идёт в два прохода — сперва поля с классом, потом свободный текст (SPEC §6.6, M-5).
- Название с реквизитом внутри (например, полное наименование с ИНН) на пути отбора по токену
  больше не открывает написание в свободном тексте того же ответа (находка C-1, Ruling 99).
- `odata.count` в ответе больше не подменяется токеном.
- Подсказка контекста «тел» в детекторе телефона срабатывает только самостоятельным словом, а не
  как часть других слов («телевизор», «Телеком»).
- Четыре поля-ссылки на контрагента/партнёра не получают класс ФИО по эвристике имени поля.
- Поле `Тип` дописывается в `$select` контактной информации, только если индекс знает его у этой
  сущности.
- Пустой литерал (`''`) в отборе по полю контактной информации принимается на обоих входных путях
  (через корень и через связь), как и непустой токен.
- `recipe check` не печатает подсказку «похожие поля» для скрытой политикой сущности.
- Пробы на живой базе копируют во временный дом и `policy.yaml`, и авторазметку `policy.auto.yaml`
  (ADR-0015) — без второго файла проба мерила гейт слабее боевого.

### Changed

- `plugin/.claude-plugin/plugin.json` — регрессионная проверка канонической сериализации.
- `main` двигается только выпусками; между выпусками рабочая ветка живёт версией `X.Y.Z.devN`.

### Docs

- Инструкция «как прописать базу вручную» — README.md и docs/install.md.

## 0.1.0 — 2026-09-14

Первый выпуск. Дистрибутив на PyPI — `odata1c-gate`, пакет Python и команда — `odata1c`.

### Чтение (этап M1)

- Демон `odata1c daemon` — единственный процесс на машину, MCP Streamable HTTP на
  `127.0.0.1:7171`; лаунчер `odata1c mcp` — тонкий stdio-процесс на сессию без собственной логики.
- Несколько баз 1С в одном `bases.yaml`, роли `prod | test | dev` с умолчаниями уровня гейта,
  разрешения записи и лимита коммитов; видимость баз сужается аргументами лаунчера.
- Индекс метаданных: разбор `$metadata` (EDMX) в SQLite, нечёткий поиск сущностей, реиндекс по
  контрольной сумме, классы полей по классификатору.
- Гейт псевдонимизации трёх уровней (`off | identifiers | identifiers+names`): реквизиты
  (ИНН, КПП, ОГРН, счета, БИК, карты, СНИЛС, документы, телефоны, почта, даты рождения, адреса),
  названия организаций и ФИО заменяются токенами `[[type:tail]]`; обратная подмена в отборах,
  ключах и параметрах — только внутри шлюза. Страж утечек — последний проход по готовому ответу.
- Девять тулов чтения: `odata1c_bases`, `odata1c_find_entity`, `odata1c_describe_entity`,
  `odata1c_query`, `odata1c_get`, `odata1c_info`, `odata1c_reindex`, `odata1c_raw_get`,
  `odata1c_recipe`; ресурсы и промпт `explore`.
- Контактная информация БСП закрывается по типу строки, адреса физических лиц, ИП и доставки — по
  правилу адресов; отбор по полям контактной информации принимается только токеном.
- Приёмка на живой базе 1С: 15 проверок из 15 чтения и 11 из 11 контактной информации
  (`docs/probes/M1d-live-check.md`).

### Запись (этап M2)

- Двухфазный протокол: пишущий тул готовит pending-операцию с превью в токенах и не трогает 1С;
  выполняет её `odata1c_commit` после подтверждения человека механизмом клиента (диалог
  разрешения Claude Code или elicitation). `commit` идемпотентен по `pending_id`.
- Семь тулов записи: `odata1c_create`, `odata1c_update`, `odata1c_mark_for_deletion`,
  `odata1c_action` (`Post`/`Unpost`), `odata1c_undo`, `odata1c_commit`, `odata1c_journal`.
- Разрешения базы проверяются до создания pending-операции; журнал коммитов и откат каждой записи.
- Подпись лаунчера ключом `launcher.key` и заверение его родительского процесса: механизм
  подтверждения Claude Code демон выдаёт только настоящему лаунчеру.
- Приёмка на живой базе 1С: 249 проверок из 249 скриптом и ручная проверка диалога разрешения
  владельцем (`docs/probes/M2-live-check.md`).

### Политика владельца (ADR-0015)

- Две точки управления: `bases.yaml` на машину («кто база, как с ней работать, скрывать ли») и
  `bases/<база>/policy.yaml` на базу («что скрывать и что открыть»). Авторазметка реиндекса
  отдельным файлом `policy.auto.yaml`, который владелец не редактирует.
- Конструктор политики: `odata1c policy show | check | hide | open | set` пишет `policy.yaml` с
  сохранением комментариев; навык плагина `odata1c-policy` ведёт к этим командам. Тула MCP для
  изменения политики нет.
- `bases.yaml` и `policy.yaml` перечитываются по изменению файла, без перезапуска демона.

### Поставка (этап M3)

- Пакет `odata1c-gate` на PyPI; установка командной строки — `uv tool install odata1c-gate`,
  запуск без установки — `uvx --from odata1c-gate odata1c …`.
- Плагин Claude Code `odata1c` из маркетплейса GitHub: MCP-сервер с закреплённой версией пакета,
  три навыка (`odata1c`, `odata1c-policy`, `odata1c-recipe`), хук `PreToolUse` и агент-следователь
  `odata1c-investigator` (только чтение).
- `odata1c doctor [--online]` — проверка окружения без секретов в выводе; `odata1c --version`.
- Библиотека рецептов по конфигурации 1С: `recipes/<конфигурация>/<имя>.yaml`, поле `config` у
  записи базы, три слоя (рецепт базы → библиотека конфигурации → шаблон пакета) и команды
  `odata1c recipe check | list`.
- Документация для внешнего читателя: `README.md`, `docs/install.md`, этот файл.
- Непрерывная проверка в GitHub Actions на Windows и Ubuntu, Python 3.12 и 3.13; выпуск на PyPI
  по тегу через trusted publishing.

### Ограничения выпуска

- Физического удаления объектов нет: только пометка удаления. `PUT` не используется. Удаление
  записей независимых регистров сведений в первую поставку не вошло.
- Записи в регистры, подчинённые регистратору, нет ни при каком флаге разрешений.
- Сокращённое название организации в свободном тексте (комментарий документа) гейт не заменяет:
  словарь знает полные написания, а ловить «ядро» названия отвергнуто из-за ложных срабатываний.
- Шаблоны рецептов заполнены только для УТ; для БП и ЗУП они пустые, пока нет базы для сверки имён.
- Строка табличной части в теле `odata1c_create` должна нести `LineNumber`, иначе 1С отвечает
  внутренней ошибкой сервиса OData; шлюз этого не проверяет. Поле `Edm.Int64` публикация отдаёт
  строкой, а шлюз на запись требует число — расхождение видно по предупреждению после перечитывания
  объекта.
- У демона нет аутентификации, он слушает только `127.0.0.1`; публикация по сети с TLS и токенами
  — этап M4.
- Поддерживается Claude Code; Claude Desktop и Cowork — нет (ADR-0012). Настоящий Claude Code на
  Linux в этом выпуске не проверялся: Linux закрыт прогонами GitHub Actions.
