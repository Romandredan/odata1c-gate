# odata1c-gate

Локальный шлюз между агентами (Claude Code и совместимые) и стандартным OData-интерфейсом 1С, который подменяет реквизиты и, на выбранном уровне, названия токенами до того, как данные увидит модель.

## Language

**База** (base):
Одна информационная база 1С с опубликованным OData-интерфейсом; именованная запись в `bases.yaml`. Имя базы — параметр каждого тула.
_Avoid_: подключение, профиль, инстанс

**Роль** (role):
Профиль умолчаний базы: `prod`, `test`, `dev`. Задаёт уровень гейта, разрешение записи, флаги разрешений и лимит коммитов; любое поле переопределяется явно.
_Avoid_: режим, тип базы

**Демон** (daemon):
Единственный локальный процесс, который держит соединения с базами, индекс, словарь и журнал; отвечает по MCP Streamable HTTP на `127.0.0.1`. Наш процесс называется демоном всегда — и в документах, и в коде, и в сообщениях модели.
_Avoid_: сервер, сервис, gate (gate — слой внутри демона)
Исключение: **«MCP-сервер»** — устоявшийся термин протокола, родовое понятие «сторона, которую запускает и опрашивает клиент»: так называют запись в `.mcp.json`, серверы других плагинов, чужой сервер вообще. В этом значении писать его можно. Подменять им имя нашего процесса нельзя: «демон другой версии», а не «сервер другой версии»; «демон слушает 127.0.0.1», а не «сервер слушает».

**Лаунчер** (launcher):
Тонкий stdio-процесс на сессию (`odata1c mcp`): создаёт домашний каталог, поднимает демон, если тот не запущен, и проксирует MCP без собственной логики.
_Avoid_: прокси, клиент, адаптер

**Домашний каталог** (home):
Каталог с настройками и данными шлюза; по умолчанию `~/.claude/odata1c/`, переопределяется `--home` или `ODATA1C_HOME`.
_Avoid_: конфиг, APPDATA

**Ключ лаунчера** (launcher key):
32 случайных байта в `launcher.key` домашнего каталога; ими лаунчер подписывает заголовки своего клиента, а демон по подписи выдаёт механизм подтверждения Claude Code только настоящему лаунчеру (Ruling 59). С секретом гейта (`gate_secret`) не смешивается.
_Avoid_: токен лаунчера (токен — значение гейта `[[type:tail]]`), секрет лаунчера, пароль

**Гейт** (gate):
Слой демона, который заменяет реквизиты и названия токенами в ответах и подставляет реальные значения вместо токенов в запросах.
_Avoid_: анонимизатор, DLP, фильтр

**Уровень** (gate mode):
Настройка базы `off | identifiers | identifiers+names`: что именно гейт заменяет.
_Avoid_: режим защиты, строгость

**Реквизит** (в смысле гейта):
Значение одного из защищаемых классов: ИНН, КПП, ОГРН, счёт, карта, СНИЛС, документ, телефон, e-mail, дата рождения, адрес. Названия и ФИО реквизитами не считаются — это отдельные классы `org` и `person`.
_Avoid_: ПДн, чувствительные данные

**Название** (name):
Наименование юридического лица или ИП (класс `org`) либо ФИО (класс `person`); заменяется только на уровне `identifiers+names` — в `Description` сущностей из `names_for`, в строковых реквизитах любой сущности по имени поля и в любых строках по словарю.
_Avoid_: имя (имя — это имя поля или сущности)

**Токен**:
Строка вида `[[type:tail]]`; единственное представление реквизита или названия, которое видит модель. Для реквизитов хвост — HMAC от секрета и нормализованного значения; для названий — порядковый номер в словаре.
_Avoid_: алиас, маска, псевдоним (алиас — отвергнутый подход с правдоподобными подменами)

**Пометка класса**:
Строка `[[org]]` или `[[person]]` без хвоста — вместо названия или ФИО, которых словарь не знает, там, где гейт маскирует без записи в словарь (журнал записи): номер названию выдаёт только запись. Не токен — не раскрывается и в отбор не годится; все неизвестные названия класса выглядят одинаково.
_Avoid_: пустой токен, токен без хвоста

**Класс** (sensitivity):
Тип заменяемого значения: `inn`, `kpp`, `ogrn`, `acc`, `corr`, `bic`, `iban`, `card`, `snils`, `doc`, `phone`, `email`, `dob`, `addr`, `org`, `person`, `custom:*`, а также служебное `keep`. Отдельно — класс токена `lit`: строка данных 1С, в которой стоит токен шлюза (вписанный текст); его назначает маскировщик по содержимому строки, классом поля по политике он не бывает.

**Словарь**:
Локальная таблица «токен → нормализованное значение и варианты написания по базам и полям»; кэш обратного отображения и источник номеров для названий. Написание — строка, в которой значение встретилось в базе (ИНН с пробелом и без, название в «ёлочках» и в прямых кавычках); у одного токена их может быть несколько: отбор по токену ищет все, а туда, где нужно одно (ключ, параметр, запись), без однозначного написания шлюз ничего не подставляет (`token_ambiguous`). У написания есть формат — текст или структура (JSON, XML контактной информации БСП: то, из чего извлекается представление, по которому построен его токен; JSON без `type`, токен которого построен по нему целиком, — текст); в поле другого формата оно не подставляется: в текстовое поле из структуры идёт её представление, в структурное — только то значение, что уже лежит в поле объекта. Формат — свойство поля, а не токена: структурным поле делает имя (`…Значение`, `…ЗначенияПолей`), поле-брат `<Имя>Строкой`, структура любого значения, виденная словарём в этом поле этой сущности (одноимённое поле другой сущности не в счёт), или структура в текущем значении. Вариант названия (ключ поиска слоя названий) — полное название и название без формы собственности; если в названии без формы нет ни одной буквы (`ООО "2020"`), вместо голого числа ключами служат оно же в кавычках (если в нём не меньше четырёх символов) и со своей формой собственности: число в тексте остаётся числом.
_Avoid_: база алиасов, vault

**Страж** (guard):
Последний проход по сериализованному ответу: известные значения словаря, оставшиеся после гейта, заменяются токенами с предупреждением.
_Avoid_: валидатор, постфильтр

**Политика** (policy):
Действующий набор правил гейта базы: правила владельца из `bases/<база>/policy.yaml` (какие сущности скрыты, какие поля к какому классу относятся, что оставить открытым, у кого скрывать названия, искать ли в тексте) поверх авторазметки. Запрет записи в поля — не политика, а разрешения.
_Avoid_: настройки гейта, правила маскирования

**Авторазметка** (auto policy):
Классы полей и умолчания, вычисленные реиндексом по индексу; файл `bases/<база>/policy.auto.yaml`, который владелец не редактирует.
_Avoid_: автополитика, auto-секция, порождённая политика

**Конструктор политики** (policy constructor):
Команды `odata1c policy …` в терминале владельца и навык плагина, которыми в политику добавляются правила; тула MCP для изменения политики нет.
_Avoid_: редактор политики, мастер, визард

**Разрешения** (permissions):
Флаги базы в `bases.yaml`: `write`, `post_documents`, `mark_deletion`, `independent_register_delete`, `register_direct_write`, `deny_entities`, `deny_fields`. Проверяются до создания pending-операции.
_Avoid_: права (права — это права пользователя 1С)

**Индекс**:
Разобранный `$metadata` базы в SQLite: сущности, поля, ключи, навигация, действия, классы полей; основа поиска и валидации.
_Avoid_: кэш метаданных, схема

**Реиндекс**:
Повторное скачивание `$metadata` и пересборка индекса с отчётом о разнице. Раздел `auto` политики пересобирается на каждом реиндексе, даже когда `$metadata` не изменился: он зависит и от классификатора шлюза.

**Сущность** (entity):
Именованный набор OData (`Catalog_Контрагенты`, `Document_X_Товары`, `AccumulationRegister_X_Balance`); табличные части и виртуальные таблицы — тоже сущности со ссылкой на родителя.
_Avoid_: объект (объект — конкретная запись), таблица

**Независимый регистр**:
Регистр сведений без регистратора (`Recorder` не входит в ключ). Единственный вид сущности, для которого допустимо физическое удаление записи по разрешению `independent_register_delete`.
_Avoid_: регистр без документа

**Рецепт** (recipe):
Именованный параметризованный запрос к одной сущности базы; типизированные параметры рендерятся в OData-литералы. Живёт файлом: собственным файлом базы (`recipes.yaml`, рецепт — запись словаря `recipes`) либо файлом библиотеки рецептов (`recipes/<config>/<имя>.yaml`, один рецепт — один файл, имя рецепта — имя файла). Заменяет тулы, привязанные к конфигурации.
_Avoid_: пресет, макрос, сохранённый запрос

**Библиотека рецептов** (recipe library):
Каталог рецептов одной конфигурации 1С (`recipes/<config>/` домашнего каталога, `config` — поле базы в `bases.yaml`), общий для всех баз с этим `config`. Средний из трёх слоёв книги рецептов базы: шаблон пакета ← библиотека конфигурации ← собственный файл базы, сильный слой при совпадении имени побеждает целиком (`recipes.model.load_layered`, ADR-0011 amended, SPEC §8). Пополняется по одному файлу рецепта, по мере того как рецепт оказывается полезен в задачах, а не разовой копией шаблона; `odata1c recipe check <config>` сверяет её с индексом.
_Avoid_: репозиторий рецептов, каталог запросов

**Pending-операция**:
Подготовленная, но не выполненная запись в 1С: превью изменений, `pending_id`, заранее выданный `commit_id`, TTL, привязка к сессии.
_Avoid_: транзакция, черновик

**Коммит**:
Выполнение pending-операции в 1С через тул `odata1c_commit` после подтверждения пользователя; идемпотентен по `pending_id`; фиксируется в журнале.

**Отпечаток**:
Состояние объекта при подготовке, с которым коммит сверяет перечитанное перед записью: `DataVersion` объекта или SHA-256 полей записи регистра (у неё `DataVersion` нет). Не совпал — `pending_stale`. Единственная защита от чужой записи между превью и коммитом: оптимистической блокировки у OData 1С нет.
_Avoid_: версия, ETag, хэш объекта

**Подтверждение**:
Действие пользователя, которое модель не контролирует: диалог разрешения Claude Code (`requiresUserInteraction`) или elicitation-диалог клиента. Реплика «да» в чате подтверждением не считается.
_Avoid_: аппрув, согласие в чате

**Журнал**:
Локальная таблица коммитов с состоянием объекта до и после в реальных значениях; основа `undo`.
_Avoid_: лог, аудит

**Откат** (undo):
Pending-операция, восстанавливающая состояние объекта по журналу; проходит тот же коммит. Её операция — та, что откатывает (`update`, `mark_for_deletion`, `action`), со ссылкой на исходный коммит; выполненный откат отмечает исходную запись журнала откаченной (`undone_by`), и второй откат той же записи не выполняется.

**Пометка удаления**:
Единственная форма «удаления» для объектов и зависимых регистров: `PATCH DeletionMark=true`.

**Маркетплейс** (marketplace):
Перечень плагинов Claude Code, по которому работает `claude plugin marketplace add`; у этого проекта — файл `.claude-plugin/marketplace.json` в корне репозитория с единственным плагином `odata1c` и источником `./plugin`. Не магазин и не хранилище: он только называет, где плагин лежит.
_Avoid_: магазин, маркет, каталог плагинов, репозиторий плагинов

**Навык** (skill):
Файл `SKILL.md` в плагине: методика для модели — когда применяется и что делать по шагам. Навыков три: `odata1c` (работа с данными 1С), `odata1c-policy` (конструктор политики, для владельца), `odata1c-recipe` (свернуть удачный запрос в рецепт). Справочники навык не дублирует: за фактами отсылает к темам `odata1c_info`, за именами объектов — к индексу, за готовыми запросами — к рецептам.
_Avoid_: скилл, инструкция, промпт (промпт — это `explore`, объект протокола MCP)

**Хук** (hook):
Скрипт `plugin/hooks/pretooluse.py`, который Claude Code вызывает перед вызовом тула (событие `PreToolUse`) и который отвечает `ask`, `deny` или молчанием. У шлюза — подтверждение на `odata1c_commit` и запрет обращений к файлам домашнего каталога. Защита в глубину, а не барьер: обход остаётся, последние линии — инвариант «реальные значения не выходят через MCP» и разрешения Claude Code на запуск инструментов.
_Avoid_: перехватчик, фильтр (фильтр — отвергнутое имя гейта), барьер

**Evals**:
Дела проверки плагина в `plugin/evals/`: вопрос модели плюс судьи, оценивающие её ответ; запускаются командой `claude plugin eval` на живой базе, поэтому в непрерывную проверку не входят. Проверяют поведение навыков и тулов целиком, а не отдельную функцию, как юнит-тест.
_Avoid_: тесты плагина, оценки, бенчмарк
